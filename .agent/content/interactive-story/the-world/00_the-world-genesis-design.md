## 1. 게임 정체성 — "목표는 정해져 있고, 삶은 정해져 있지 않다"

### 1.1 설계 원칙

1. **기본 목표는 고정, 경로와 결과는 열려 있다.** 하린의 정의(Definition)에 박힌 꿈은 바뀌지 않는다. 하지만 지금 쫓는 목표(State)는 사용자의 선택으로 바뀔 수 있다 — 규약 §5.2의 정의/상태 분리를 게임 규칙으로 옮긴 것이다.
2. **실패는 게임 오버가 아니라 다음 장의 조건이다.** 돈이 바닥나면 아르바이트로 돌아가고, 번아웃이 오면 쉬어야 하고, 브랜드가 문을 닫으면 그 경험이 다음 도전의 능력이 된다. 어떤 상태에서도 **회복 경로가 하나 이상** 있다.
3. **현실의 인과를 따른다.** 운은 있지만 운만으로 가지 않는다. 팔로워는 늘어도 구매로 바로 이어지지 않고, 크게 만들면 재고가 남고, 쉬지 않으면 무너진다. 게임의 규칙이 곧 Intelligence 지식의 체험이다.
4. **엔딩이 없다.** 브랜드를 열어도, 실패해도, 다른 길을 가도 시간은 흐르고 라이프 이벤트는 계속 온다. "끝"이 아니라 "지금 어디에 있는가"만 있다.
5. **AI는 이야기를 만들고, 규칙은 결과를 정한다.** AI 모드에서도 숫자(돈·능력·평판)는 결정적 규칙 엔진이 계산한다. AI는 사건 제안·연출·대화만 맡는다(§6.3).

| Growth Potential | "보여지는 사람" → "만드는 사람" → "이끄는 사람" |

- **기본 목표(Want)는 고정**이다. 사용자가 다른 커리어를 고르면 하린의 **현재 목표(State)**가 바뀔 뿐, 꿈 자체는 정의에 남는다. 그래서 다른 길을 가던 하린에게도 "다시 내 브랜드를 해 볼까" 하는 계기 이벤트가 나중에 올 수 있다(§4.6 귀환 이벤트).
- **안전 메모(규약 §9.2 Safety)**: 체중·다이어트·외모 비교를 **수치나 목표로 만들지 않는다**. 외모 압박은 업계 구조(오디션 피드백·계약 조항)로만 다루고, 대응 선택지에는 항상 건강한 선택이 있다.

### 2.2 핵심 인물 (공식 캐릭터 후보 — 규약 §4.3 승인 대상)

캐스팅 상한(규약 §7.4)에 맞춰 공식 인물은 5명으로 시작한다. 그 밖의 인물은 §2.3의 **역할형 NPC**로 채운다.

| 인물(가) | 역할 | 하린과의 시작 관계 | Want / Fear | 게임 내 기능 |
| --- | --- | --- | --- | --- |
| **지유** | 룸메이트이자 동갑 친구. 낮에는 회사원, 밤에는 사진을 찍는다 | `ally` | 안정된 삶 / 꿈을 포기한 걸 후회하는 것 | 무료 촬영·정서 회복. 하린이 성공할수록 관계에 긴장이 생길 수 있음 |
| **강 실장** | 중소 모델 에이전시 캐스팅 실장 | `unknown` | 회사를 지키는 것 / 회사가 흔들리는 것(숨긴 사정) | 모델 커리어 관문. 계약·스케줄·조항 갈등 |
| **문 사장** | 원단 거리 끝 샘플실 사장. 30년 차 패턴사 | `unknown` | 소량 생산 공방을 지키는 것 / 골목 공방들이 문 닫는 것 | 브랜드 준비의 관문. 원가·최소 주문 수량·생산 현실 |
| **세라** | 같은 시기 활동하는 모델 지망생 | `unknown` → 상황에 따라 `rival` 또는 `ally` | 빨리 뜨는 것 / 잊히는 것 | 비교·경쟁 압박, 협업 기회. 하린의 거울 |
| **엄마** | 지방에서 작은 옷 수선집을 하는 어머니 | `kin` | 딸이 안정적으로 사는 것 / 딸이 다치는 것 | 현실적 압박과 마지막 안전망. 수선 기술(숨은 자산) |

- **엄마의 수선집**은 Character Subplot의 씨앗이다. 하린이 "보여지는 일"만 보다가, 나중에 옷을 **만드는** 뿌리가 엄마에게 있었다는 것을 발견하는 회수 지점이 된다.
- 관계 배타 쌍(`ally↔rival` 등)은 코드에서 동시 선언이 차단된다. 세라는 `unknown`에서 시작해 사용자 선택에 따라 **사용자별 진행**에서 한쪽으로 기운다(공식 Canon은 고정 루트 기준만).

### 2.3 역할형 NPC 풀 (공식 Canon 아님)

AI 모드와 이벤트 덱이 상황에 맞게 배치하는 **익명 역할**이다. 이름·외형은 런타임에서 부여하고 공식 Canon에 저장하지 않는다(Character Inflation 방지).

### 2.5 플레이어 이름 설정 — "이야기 속의 하린, 내 게임 속의 ○○"

**원칙**: 공식 이야기의 주인공은 하린이다. 사용자가 Play에서 이 캐릭터를 고르는 순간, 그 캐릭터는 **사용자의 캐릭터 인스턴스**가 되고 이름은 사용자가 정한다.

| 표면 | 이름 | 이유 |
| --- | --- | --- |
| Home Story(인터랙티브 아티클) | **하린** 고정 | 공식 Canon·출판 콘텐츠. 모든 사용자가 같은 이야기를 본다 |
| 공식 Canon(캐릭터·관계·사건 revision) | **하린** 고정 | 개인 설정이 공식 세계로 새지 않는다(규약 §4.2) |
| Play 모드 A(고정 루트) | **사용자가 정한 이름** | 같은 고정 이벤트를 "내 캐릭터"로 플레이 |
| Play 모드 B(AI 시뮬레이션) | **사용자가 정한 이름** | AI 서술·대화에도 그 이름을 쓴다 |
| Play CharacterChat | **사용자가 정한 이름** | NPC가 그 이름으로 부른다 |

**무엇이 바뀌고 무엇이 그대로인가**

| 사용자가 정한다 | 바뀌지 않는다 (공식 정의 유지) |
| --- | --- |
| 이름(표시 이름) | 외형(캐릭터 시트·액션 시트·스프라이트) — 장면마다 바뀌면 Canon Drift |
| | 나이·출신·성격·Want/Fear·기본 목표 |
| | 핵심 인물과의 시작 관계 |

> 외형 커스터마이즈는 이 설계 범위가 아니다. 공식 캐릭터의 에셋을 그대로 쓰는 것이 "게임 에셋 기반 Story"의 전제다(TEMP).

**선택 흐름**

```text
Home Story 끝 CTA "이 캐릭터로 나만의 스토리 시작하기"
→ 캐릭터 카드(하린 소개 · 외형)
→ 이름 입력 (기본값 "하린", 그대로 시작 가능)
→ 모드 선택: 고정 루트(공식 출발 그대로) / AI 시뮬레이션
→ (AI 시뮬레이션) 출발 목표 선택 — §2.6.4
→ 시작 — 첫 장면에서 NPC가 새 이름으로 부른다
```

**이름 규칙 (제안 — 최종 값은 구현 계약에서 확정)**

| 규칙 | 내용 |
| --- | --- |
| 길이 | 한글 1~8자 / 영문 1~12자 (UI 말풍선·조사 처리 기준) |
| 허용 문자 | 한글·영문·공백 1개. 숫자·특수문자·이모지 불가 |
| 차단 | 욕설·혐오 표현, 실존 유명인·공인 이름(사칭 방지), 핵심 인물 이름(지유·세라 등 — 혼동 방지), 내부 예약어 |
| 개인정보 고지 | 입력란에 "실명 대신 캐릭터 이름을 권장" 안내. 이름은 실명일 수 있으므로 **개인정보에 준해 다룬다**(아래) |
| 변경 | 시작 후 1회 변경 허용(제안). 변경 시 과거 기록의 표시도 새 이름으로 바뀐다(이름은 표시값이고 식별자가 아니다) |
| 다국어 | 영어 UI에서는 입력한 이름을 그대로 쓴다. 기본값은 "Harin" |

**텍스트 처리 — 한국어 조사**

모든 작성 텍스트(고정 루트 대사·이벤트·Intelligence 카드 획득 문구)는 이름을 직접 쓰지 않고 **토큰**으로 쓴다.

```text
작성 원고   "{name:이/가} 거울 앞에 섰다."  "{name:아/야}, 오늘 촬영 몇 시야?"
하린        "하린이 거울 앞에 섰다."         "하린아, 오늘 촬영 몇 시야?"
수아(예)     "수아가 거울 앞에 섰다."         "수아야, 오늘 촬영 몇 시야?"
```

- node-app에 `utils/language/getKorParticle.ts`가 있다(이 브랜치 스냅샷 기준: `을/를 · 이/가 · 은/는 · 과/와 · 으로/로 · 이랑/랑`, 영문 이름 받침 추정 포함). **호격 `아/야`, 서술격 `이에요/예요`·`이라고/라고`는 없다** → 추가 필요.
- 한국어에서는 받침 있는 이름을 부를 때 "수진이가"처럼 `이`를 붙이는 구어 습관이 있다. 대사 톤에 따라 `{name:friendly}`(수진이) 형태를 둘지는 작가 스타일 가이드에서 정한다(제안: NPC 친밀도가 높을 때만).
- **AI 모드**: AI 프롬프트에는 표시 이름을 넣고, 출력 검증에서 공식 이름 "하린"이 섞여 나오면 표시 이름으로 교체하거나 재생성한다. 표시 이름은 프롬프트 주입 경로가 될 수 있으므로 허용 문자 규칙으로 막는다(현행 Director의 injection 패턴 검사와 같은 경계).

**데이터와 Canon**

- 공식 캐릭터 ID는 그대로 `tw-char-harin`이다. 사용자 캐릭터는 코드의 `playerCharacterInstanceId` 단위로 존재하고, 표시 이름은 **그 인스턴스의 속성**으로 둔다(현재 스냅샷에는 인스턴스 표시 이름 필드가 없다 — 구현 계약 필요).
- 표시 이름은 사용자 진행 데이터다. `G-ISC-DATA`(ISC-000) 판정 범위에 포함하고, 회원 탈퇴·삭제 요청 시 함께 삭제한다.
- 공식 Canon·Home Story·집계 분석에 표시 이름을 쓰지 않는다. 분석은 이름이 아니라 익명 인스턴스 기준이다.
- NPC의 Character Knowledge 관점에서 "하린"과 "사용자 이름"은 같은 인물이다. NPC는 사용자 캐릭터를 언제나 표시 이름으로 알고 부른다.

**Story → Play 연결 문구**

- Home Story 끝 화면: "하린의 이야기, 이제 당신의 이름으로 이어 가세요." — 같은 인물이 이름만 바뀐다는 점을 분명히 한다.
- Story에서 한 선택이 Play 시작 상태에 반영될 때(§8)도 이름과 무관하게 같은 인스턴스로 이어진다.

### 2.6 출발 설정 — 공식 하린과 사용자의 하린

#### 2.6.1 왜 나누는가

- 캐릭터의 **정의**(외형·성격·Want/Fear·기본 목표)는 하나다. 그러나 **어디서 출발하는가**(일·돈·팔로워·첫 목표)는 이야기마다 달라도 된다.
- 공식 하린의 출발은 **공식 이야기 하나**를 위한 설정이다. 모든 사용자가 같은 출발로 시작하면 Home Story를 이미 본 사용자에게 Play가 "아는 이야기의 반복"이 된다.
- 그래서 출발 설정(Origin)을 **캐릭터 인스턴스의 시작 상태**로 둔다. 공식 Canon에는 공식 출발만 기록한다.

#### 2.6.2 공식 출발 — "팔로워 0명"

| 항목 | 값 |
| --- | --- |
| 일 | 골목 상가의 **작은 옷가게** 아르바이트(가: 「오늘의 옷장」). 사장님 혼자 운영하는 보세 매장 — 매장 진열·손님 응대·가끔 사장님의 SNS 사진 모델 |
| 거처 | 반지하 원룸, 룸메이트 지유 |
| 돈 | 한 달 생활비를 겨우 맞추는 수준 |
| 팔로워 | **0명** — 계정이 없다. "언젠가"라며 미뤄 왔다 |
| 첫 목표 | **팔로워 모으기** — 첫 마일스톤은 팔로워 1,000명(자리표시 값) |
| 강점 | 매장에서 매일 보는 "실제로 팔리는 옷"에 대한 감각 |
| 약점 | 카메라 앞 경험 없음, 콘텐츠 제작 경험 없음, 업계 인맥 없음 |
| 첫 갈림길 | 사장님의 제안: "가게 옷 입고 사진 한번 올려 볼래?" |

- 매장 사장님은 공식 플레이에서 자주 등장할 인물이다. 우선 역할형 NPC(`매장 점장` → `작은 옷가게 사장`)로 두고, 공식 이야기에서 비중이 커지면 공식 캐릭터 승격을 검토한다(규약 §7.4 판단식).

#### 2.6.3 공식 플레이 (Canon Run)

```text
운영자가 공식 출발 설정으로 Play를 한 명의 유저로서 진행
→ 매주의 활동·사건·선택이 기록된다 (그 자체는 아직 Canon이 아니다)
→ 편집: 이야기가 될 만한 구간을 골라 Production Brief 작성 (규약 §7·§8)
→ 검수·사람 승인 → Home Story 출판 + 해당 사건·관계 변화를 Canon revision으로 승인 (admin)
→ 출판된 구간이 모드 A(고정 루트)의 챕터가 된다
```

- **공식 플레이도 AI 모드로 진행할 수 있다.** 다만 AI가 만든 사건은 플레이 기록일 뿐이고, Canon이 되는 것은 **편집 판단 + admin 승인**을 거친 것뿐이다(규약 §4.3 — AI는 Canon을 확정하지 않는다).
- 공식 플레이는 Home Story보다 **몇 주 앞서** 진행한다. 연재 간격을 확보하고, 검수에서 걸린 구간을 다시 편집할 여유를 둔다.
- 공식 플레이에서 실패도 그대로 이야기가 된다. 편집은 "재미있는 구간"을 고르는 것이지 결과를 고치는 것이 아니다. 결과를 바꾸고 싶으면 다음 선택으로 바꾼다(append-first).
- 공식 플레이 계정은 운영 계정이며, 그 진행 데이터는 일반 사용자 데이터와 분리해 둔다(Canon 원천 기록).

#### 2.6.4 다른 사용자의 출발 — 목표 선택지

다른 사용자가 이 캐릭터를 고르면 공식 출발을 반복하지 않고, **출발 목표를 고른다.** 기본 목표(자기 이름의 브랜드)는 모두 같고, 그곳으로 가는 **첫 길**이 다르다.

| 선택지(가) | 출발 상황 | 첫 목표 | 처음부터 강한 것 | 처음에 부족한 것 | 고유 초반 이벤트 |
| --- | --- | --- | --- | --- | --- |
| **런웨이를 향해** | 카페 아르바이트 + 모델 아카데미 수강생 | 에이전시와 첫 계약 | 모델링 | 돈·콘텐츠 | 아카데미 쇼케이스, 첫 오디션, 수강료 압박 |
| **내 옷 먼저** | 고향 엄마의 수선집 일을 돕다 막 상경 | 리폼 옷 첫 판매 | 디자인·제작 | 팔로워·도시 인맥 | 플리마켓 첫 판매, 원단 거리 첫 방문, 엄마의 반대 |
| **현장 막내** | 스타일리스트 어시스턴트(막내) | 한 시즌 버티기 | 스타일링·네트워크 | 시간·컨디션·돈 | 촬영장 밤샘, 협찬 의상 분실 사고, 모델 대타 기회 |
| **퇴근 후의 꿈** | 사무직 회사원, 주말에만 활동 | 첫 협찬 받기 | 자금·비즈니스 감각 | 시간·모델링 | 회사 겸업 규정, 주말 촬영, 퇴사 고민 |

- 공식 출발("팔로워 0명")과 같은 출발로 하고 싶은 사용자는 **모드 A(고정 루트)**를 고르면 된다. 모드 B의 선택지에는 공식 출발을 넣지 않는다.
- 선택지는 **출발 상태(자원·능력·해금 구역)와 초반 이벤트 덱**만 바꾼다. 캐릭터 정의·외형·핵심 인물은 같다. 핵심 인물과 만나는 시점과 계기가 출발마다 다를 뿐이다(예: "내 옷 먼저"는 문 사장을 일찍, 강 실장을 늦게 만난다).
- 첫 목표를 이룬 뒤에는 모든 출발이 같은 커리어 페이즈 구조(§4)로 합류한다. 중간에 목표를 바꾸는 것도 똑같이 가능하다(§4.5).
- 출발 선택지는 시즌마다 추가할 수 있다. 처음 출시는 4개, 각 출발의 고유 초반 이벤트는 8~12개(자리표시 값)로 시작한다.
- 화면 문구는 "출발 설정"이 아니라 **"하린은 지금 어디에 서 있나요?"**처럼 이야기 언어로 묻는다(내부 용어 비노출, 규약 §2).

| 골목 상가 (작은 옷가게) | 시작(공식 출발) | 아르바이트, 매장 진열, 손님 관찰, 사장님 SNS 촬영 | `commerce market` |
| 동네 공원·강변 | 시작 | 산책·운동(컨디션 회복), 야외 촬영 | `central plaza` 변형 |
| 아카이브 | 시작 | Intelligence 학습(카드 해금) | `learning district` |
| 모델 아카데미 | 시작(수강료 필요) | 워킹·포즈 클래스, 프로필 촬영 | `training arena` 변형 |
| 스튜디오 지구 | 첫 촬영 의뢰 또는 지유와의 촬영 | 촬영, 협업, 포트폴리오 | `central plaza` |
| 에이전시 빌딩 | 강 실장과 첫 만남 | 오디션, 계약, 스케줄 | `central plaza` 변형 |
| 원단 거리 | 브랜드 관심 플래그 | 원단·부자재 소싱, 시장 조사 | `commerce market` |
| 문 사장의 샘플실 | 문 사장과 첫 만남 | 샘플 제작, 생산 상담 | `commerce market` 변형 |
| 팝업 스트리트 | 첫 판매 시도 | 팝업 판매, 고객 반응 | `central plaza` |
| *(경영 페이즈)* 하린의 쇼룸·사무실 | 브랜드 런칭 | 팀·재고·주문·마케팅 관리 | `commerce store fixtures` |

### 3.2 시간 — 주간 플래너와 시즌

- **기본 단위는 1주.** 한 주는 7일 × 3칸(오전·오후·저녁) = 21칸이다. 사용자는 활동을 칸에 배치하고 "한 주 보내기"를 누른다.
- **일부 칸은 고정된다.** 아르바이트 근무, 계약된 촬영, 수업은 미리 칸을 차지한다. 돈을 벌수록 시간이 줄어드는 현실적 긴장이 여기서 생긴다.
- **시즌 캘린더**: 패션 업계의 계절 리듬을 따른다 — S/S·F/W 시즌, 시즌 오프 세일, 연말 성수기, 신학기. 시즌마다 오디션 수요·협찬 단가·판매 수요가 달라진다.
- **나이와 해(年)가 흐른다.** 하린은 나이를 먹는다. 나이 자체에 페널티를 주지 않지만, 시간이 흐른다는 감각이 선택의 무게를 만든다.

### 3.3 자원

| 자원 | 의미 | 바닥나면 |
| --- | --- | --- |
| 돈 | 월세·생활비·수강료·촬영비·원단비 | 강제 아르바이트 추가, 기회 포기, 가족에게 손 벌리기 이벤트 |
| 컨디션 | 체력·에너지 (외모 지표 아님) | 활동 효율 하락 → 지속되면 번아웃 상태 |
| 마음(스트레스의 반대) | 정서적 여유. 비교·악플·실패로 줄고 휴식·관계·성취로 회복 | 충동적 선택지만 보이는 "흔들림" 상태 |
| 시간 | 주 21칸 | — (매주 리셋) |

### 3.4 능력치 (활동과 학습으로 성장, 사용하지 않으면 천천히 녹슮)

| 능력 | 키우는 활동 | 쓰이는 곳 |
| --- | --- | --- |
| 모델링 (포즈·워킹·표현) | 아카데미, 촬영 | 오디션, 촬영 품질 |
| 스타일링 감각 | 매장 근무, 코디 콘텐츠, 트렌드 체크 | 콘텐츠 반응, 디자인 방향 |
| 콘텐츠 제작 (촬영·편집·기획) | 업로드, 지유와 촬영 | 팔로워 성장, 협찬 품질 |
| 소통 (팬·관계) | 댓글 소통, 라이브, 만남 | 신뢰도, 위기 대응 |
| 디자인·제작 | 스케치, 엄마에게 배우기, 샘플실 | 샘플 품질, 브랜드 정체성 |
| 비즈니스 감각 (숫자·협상) | 아카이브 학습, 매장 재고 관찰, 협상 | 계약 조건, 원가·가격 판단 |
| 네트워크 | 파티, 협업, 업계 행사 | 기회 이벤트 발생률 |

### 3.5 평판 — 도달과 설득을 따로 센다

| 지표 | 의미 | 늘리는 것 | 쓰이는 곳 |
| --- | --- | --- | --- |
| **팔로워** (도달) | 얼마나 많은 사람이 보는가 | 업로드 빈도, 바이럴, 협업 | 협찬 제안 빈도 |
| **신뢰도** (설득) | 본 사람이 하린의 추천을 믿는가 | 솔직한 리뷰, 광고 표시, 팬 소통, 약속 이행 | **실제 판매 전환**, 협찬 단가, 위기 회복력 |
| 업계 평판 | 에이전시·브랜드·공방이 보는 하린 | 촬영 태도, 계약 이행, 품질 | 오디션 합격, 캐스팅, 공방 협조 |
| 포트폴리오 | 쌓인 작업의 질 | 촬영·작업 결과 | 오디션·투자 |

- **팔로워가 많아도 신뢰도가 낮으면 팔리지 않는다.** 판매 계산은 팔로워보다 신뢰도의 영향을 더 크게 받는다. 자매 기사 「조회수는 평범한데 광고 단가는 높은 콘텐츠」의 지식이 게임 규칙으로 들어온 지점이다.
- 숨은 광고, 과장 리뷰는 단기 팔로워·수입을 주지만 신뢰도를 깎고, 들키면 크게 깎는다.

### 3.6 관계

- 핵심 인물 5명은 친밀도(코드 `relation.affinity.adjust`)와 관계 유형을 갖는다.
- 관계는 시간이 지나면 식는다. 바쁜 시기에 지유와의 저녁을 계속 빼면 관계 이벤트가 생긴다.
- 관계는 자원이기도 하다: 지유의 무료 촬영, 엄마의 수선 기술, 문 사장의 생산 일정 양보.

## 4. 커리어 페이즈 — 정해진 순서가 아니라 열리는 문

```text
[P1 지망생] ──첫 유료 일──▶ [P2 활동기] ──브랜드 준비 조건──▶ [P3 브랜드 준비] ──런칭──▶ [P4 경영]
     ▲                         │  ▲                              │                          │
     └──── 실패·휴식·재도전 ────┘  └──────── 보류·피벗 ───────────┘◀──── 폐업·축소·매각 ──────┘
                 │
                 └──▶ [다른 길] 스타일리스트 · 패션 MD · 디자이너 취업 · 포토그래퍼 · 다른 창업 · 평범한 직장
```

### 4.1 P1 지망생 — "보여지고 싶은 사람"

| 항목 | 내용 |
| --- | --- |
| 첫 목표 | 출발에 따라 다르다 — 공식 출발은 **팔로워 모으기**(첫 마일스톤 1,000명, 자리표시 값) |
| 하루 | 아르바이트로 생활비를 벌고, 남는 칸에 촬영·업로드·수업·오디션을 넣는다 |
| 핵심 긴장 | 돈 vs 시간. 수강료를 내면 월세가 빠듯하다 |
| 주요 이벤트 | 오디션(합격·불합격), 노페이 촬영 제안, 수상한 에이전시의 "등록비" 요구, 첫 바이럴, 엄마의 전화 |
| 다음 페이즈 문 | **첫 유료 일** — 에이전시 계약, 유료 촬영, 첫 협찬 중 하나 |
| 실패의 모습 | 오디션 연속 탈락, 사기 피해, 생활비 고갈 → 아르바이트 시간 증가. 포기가 아니라 속도가 느려진다 |

### 4.2 P2 활동기 — "보여지는 사람"

두 갈래를 함께 또는 따로 키운다.

| 갈래 | 성장 축 | 대표 갈림길 |
| --- | --- | --- |
| 모델 | 업계 평판·포트폴리오·모델링 | 에이전시 전속 계약(안정 vs 조항 제약), 큰 캠페인 오디션 vs 작은 단골 일 |
| 인플루언서 | 팔로워·신뢰도·콘텐츠 | 협찬 수락 기준, 광고 표시, 논란 대응, 업로드 빈도 vs 번아웃 |

- **핵심 긴장**: 일이 늘수록 내 것(디자인)을 할 시간이 사라진다. 그리고 남의 브랜드의 얼굴로 사는 게 편해진다.
- **P3로 가는 문(예시 조건 — 밸런싱 전)**: 자금이 일정 이상 · 디자인·제작 능력 일정 이상 · 신뢰도 일정 이상 · "내 옷을 만들고 싶다" 플래그(스케치 활동 누적 또는 귀환 이벤트). 조건이 충족돼도 **사용자가 문을 열어야** 들어간다.

### 4.3 P3 브랜드 준비 — "만드는 사람"

| 항목 | 내용 |
| --- | --- |
| 활동 | 시장 조사, 원단 소싱, 샘플 제작, 수요 확인(사전 예약·대기 신청), 가격 책정, 브랜드명·정체성 |
| 핵심 긴장 | 크게 시작(단가↓·재고 위험↑) vs 작게 시작(단가↑·속도↓). 팔로워의 "살게요"와 실제 결제의 차이 |
| 관문 인물 | 문 사장(생산 현실), 강 실장(계약 조항·이탈 비용) |
| 런칭 조건 | 샘플 확정 + 초기 생산 자금 + 판매 채널 1개 이상 |
| 실패의 모습 | 샘플 반복 실패로 자금 소진, 사전 예약 미달, 계약 위약금 → 준비 보류(P2 복귀) 또는 규모 축소 |

### 4.4 P4 경영 시뮬레이션 — "이끄는 사람" (자연 전환)

브랜드를 런칭하면 **게임의 층이 하나 추가된다.** 하린의 삶(주간 플래너)은 계속되고, 그 위에 브랜드 관리 화면이 열린다.

| 요소 | 내용 |
| --- | --- |
| 턴 | 브랜드는 **월 단위**로 결산한다. 하린의 주간 플래너와 병행 — 하린이 브랜드 일에 쓴 칸이 브랜드의 역량이 된다 |
| 관리 대상 | 상품 라인업 · 생산 수량(최소 주문 수량) · 원가·가격 · 재고 · 판매 채널(자사몰·팝업·입점) · 마케팅(본인 채널·협업·광고) · 현금흐름 · 팀(첫 직원 채용·위임) |
| 핵심 긴장 | 품절인데 현금이 없다 · 잘 팔린 걸 또 만들까, 믿는 걸 만들까 · 하린 본인 채널 의존도 vs 브랜드 독립 · 성장 vs 번아웃 |
| 브랜드 지표 | 매출, 재고 회전, 현금 잔고, 브랜드 신뢰, 재구매 고객, 팀 사기 |
| 이벤트 | 대형 입점 제안, 카피 제품 등장, 공장 납기 지연, 리오더 결정, 투자 제안, 시즌 실패, 직원 퇴사 |
| 실패의 모습 | 재고 누적·현금 고갈 → 구조조정·축소·폐업. **폐업해도 게임은 이어진다** — 하린은 경험·능력·관계를 갖고 P2 또는 다른 길로 돌아간다 |
| 성공의 모습 | 브랜드가 커질수록 하린은 "얼굴"에서 "경영자"로 바뀐다. 새로운 문제(팀·투자·확장)가 계속 온다. 끝은 없다 |

- v1의 Story 소재(최소 주문 수량·가격표·협찬과 신뢰·현금흐름·두 번째 컬렉션)는 **P3·P4의 시뮬레이션 규칙과 이벤트**로 들어간다.

### 4.5 다른 길 — 목표 변경

- **목표 재설정 갈림길**은 실패 누적, 큰 기회, 라이프 이벤트 뒤에 열린다. 사용자는 하린의 현재 목표를 바꿀 수 있다.
- 다른 길도 같은 도시·능력·관계 위에서 이어진다: 스타일리스트(스타일링 감각), 패션 MD(비즈니스 감각·매장 경험), 디자이너 취업(디자인), 포토그래퍼(지유와의 관계·콘텐츠), 다른 업종 창업, 평범한 직장 생활.
- 다른 길에도 각자의 성장·실패·이벤트가 있다. 처음 출시에는 **스타일리스트·패션 MD 2개만** 깊게 만들고, 나머지는 "선택 가능하지만 이벤트가 적은" 상태로 시작한다(제작 범위 관리).

### 4.6 라이프 이벤트 — 현실처럼, 그러나 안전하게

| 분류 | 예시 |
| --- | --- |
| 커리어 | 오디션 결과, 캐스팅·협찬 제안, 계약 분쟁, 경쟁자의 성공 |
| 시장 | 트렌드 급변, 플랫폼 노출 방식 변화, 원단값 상승, 시즌 수요 |
| 관계 | 지유와의 갈등·화해, 세라와의 경쟁·협업, 엄마의 건강, 멘토의 등장 |
| 위기 | 악플·논란, 사기 제안, 번아웃, 사고로 인한 촬영 취소 |
| 행운 | 우연한 바이럴, 은인의 소개, 좋은 원단 발견 |
| 귀환 | 다른 길을 가던 하린에게 오는 "다시 내 옷을" 계기 — 엄마의 수선집 정리, 옛 스케치 노트 발견 |

- **모든 위기 이벤트에는 회복 선택지가 있다.** 위기 자체보다 대응이 하린을 바꾼다.
- 다루지 않는 것: 체중·외모 수치, 자해, 성적 착취 묘사, 실존 인물·브랜드, 투자·대출 권유. 업계 부조리(사기 에이전시, 노페이 관행)는 **알아보고 피하는 판단**을 연습하는 사건으로만 다룬다.

## 5. 공식 이야기와 모드 A — 고정 루트 (AI 미사용)

### 5.1 성격

- 공식 이야기는 **공식 플레이(§2.6.3)의 전개**를 따라간다. 작가가 미리 다 써 둔 이야기가 아니라, 운영자가 Play에서 실제로 진행한 한 사람의 이야기를 편집해 연재한다.
- 출판된 구간은 **모드 A의 챕터**가 된다. 모드 A 사용자는 공식 하린과 같은 출발(팔로워 0명)에서 시작해, 출판된 챕터의 고정 이벤트를 따라간다.
- 모드 A에도 선택지는 있다. 결과는 **작성된 결과표**에서 나오고, 갈래는 일정 지점에서 다시 합류한다(병목형 분기). 공식 하린이 고르지 않은 선택지의 결과도 결과표에 쓴다.
- 주간 플래너·자원·능력 시스템은 그대로 쓴다. 이벤트는 덱이 아니라 **챕터 순서**로 온다.
- 아직 출판되지 않은 구간에 도달하면: "다음 이야기는 준비 중" 상태로 덱 기반 일상(아르바이트·촬영·업로드)을 계속하거나, 모드 B로 넘어갈 수 있다. 모드 B로 넘어가면 지금까지의 상태를 이어받는다.
- 비용이 들지 않고, 처음 하는 사용자에게 세계·인물·규칙을 소개하는 튜토리얼 역할도 한다.

### 5.2 공식 플레이의 초반 전개 계획 (편집 가이드 — 실제 전개는 공식 플레이 결과를 따른다)

공식 플레이는 결과가 정해져 있지 않다. 아래는 **공식 출발에서 나올 가능성이 높은 사건과 편집 포인트**를 정리한 계획이며, 실제 챕터는 플레이 결과에 맞춰 다시 쓴다.

| Ch | 제목(가) | 페이즈 | 계획 사건 | 예상 갈림길 | 다루는 판단(Intelligence) |
| --- | --- | --- | --- | --- | --- |
| 1 | 팔로워 0명 | P1 | 사장님의 제안 "가게 옷 입고 사진 한번 올려 볼래?" — 계정 개설, 첫 게시물 | 얼굴을 보여 준다 / 옷만 찍는다 / 매장 계정에 먼저 올린다 | 첫 콘텐츠는 무엇을 보여 줘야 하나 |
| 2 | 아무도 안 본다 | P1 | 일주일 내내 반응 없음. 지유는 "매일 올려 봐", 사장님은 "옷 설명을 써 봐" | 매일 올리기 / 한 주에 하나를 제대로 / 다른 계정 따라 하기 | 꾸준함 vs 한 방 |
| 3 | 긴 머리 지망생 | P1 | 처음 가 본 모델 오디션, "긴 머리 지망생이 너무 많다"는 피드백 → 숏컷 결심 | 머리를 자른다 / 그대로 간다 | 차별화는 무엇으로 만드는가 |
| 4 | 친구의 카메라 | P1 | 지유와 첫 제대로 된 촬영, 숏컷 사진이 처음으로 반응을 얻는다 | 반응 좋은 스타일 반복 / 하고 싶은 스타일 고집 | 반응을 어디까지 따를까 |
| 5 | 등록비 30만 원 | P1 | 팔로워가 늘자 온 캐스팅 DM, 알고 보니 등록비 요구 | 낸다 / 알아본다 / 거절한다 | 좋은 기회와 사기를 가르는 신호 |
| 6 | 팔로워 1,000명 | P1 | **첫 목표 달성**(또는 정체). 다음 목표를 정하는 갈림길 | 모델 쪽으로 / 인플루언서 쪽으로 / 둘 다 | 숫자 다음에 무엇을 볼 것인가 |
| 7 | 첫 유료 일 | P1→P2 | 강 실장의 연락, 작은 캠페인 | 조건 협상 여부 | 첫 계약에서 볼 것 |
| 8~ | (공식 플레이 진행에 따라) | P2~ | 후보: 세라의 급성장 · 광고 표시 · 전속 계약서 · 엄마의 수선집 · 살게요 92% · 300벌의 약속 · 가격표 · 첫 팝업 · 경영 시즌 | — | 도달과 신뢰 · 계약 · 수요 확인 · 최소 주문 수량 · 가격 · 현금흐름 |

- 8장 이후 후보는 v2의 공식 루트 초안(전속 계약서·엄마의 수선집·살게요 92%·300벌의 약속 등)을 **소재 풀**로 남긴 것이다. 공식 플레이가 그쪽으로 가지 않으면 쓰지 않는다.
- 공식 이야기도 끝나지 않는다. 브랜드 런칭 뒤에는 경영 시즌으로 이어지고, 실패하면 실패 이후의 이야기가 이어진다.
- 각 챕터의 Intelligence 주제는 규약 §7.2 Worthiness Gate를 다시 통과해야 제작한다(Story Dictated Content 금지). 근거 기사가 없는 챕터는 근거 확보 전까지 보류한다.

### 5.3 고정 루트 안에서의 실패

고정 루트에도 실패 결과가 있다. 예: Ch5에서 등록비를 내면 돈과 마음이 깎이고, 그 경험이 이후 계약서 장면에서 "조항을 꼼꼼히 읽는" 선택지를 해금한다. **실패가 다음 챕터의 능력이 된다**는 원칙은 두 모드 모두 같다.

## 6. 모드 B — AI 시뮬레이션 (AI 사용)

### 6.1 성격

- 챕터가 없다. **출발 목표(§2.6.4)를 고른 뒤**, 매주 사용자가 활동을 배치하고, **결과와 사건이 하린의 상태에서 생긴다.**
- 같은 시작에서 출발해도 사용자마다 전혀 다른 하린이 된다: 3년째 지망생인 하린, 모델로 자리 잡았지만 브랜드는 미룬 하린, 브랜드를 열었다 닫고 스타일리스트가 된 하린, 엄마의 수선집을 이어받아 리폼 브랜드를 만든 하린.
- 핵심 인물 5명은 같은 정의(Definition)로 등장하지만, 관계와 사건은 사용자마다 다르다.

### 6.2 한 주가 돌아가는 방식

```text
1. 사용자: 주간 플래너에 활동 배치
2. 규칙 엔진: 활동 결과 계산 (돈·컨디션·마음·능력·평판·관계)        ← 결정적, AI 미사용
3. 이벤트 선택: 상태 조건에 맞는 이벤트 덱에서 후보 추출              ← 결정적
4. AI Narrative Director: 하린의 현재 상태·관계·최근 사건을 보고
   이번 주 "사건 1건"을 제안 (덱 이벤트 개인화 또는 새 사건 후보)     ← AI, proposal-only
5. 검증: 제안이 허용된 효과·세계 규칙·안전 기준 안인지 확인
   통과 → 이벤트로 연출 / 실패 → 덱 이벤트로 대체(fallback)
6. 사용자: 사건에서 선택
7. 규칙 엔진: 선택의 결과 계산 → 상태 갱신 → 사용자별 Narrative Runtime에 기록
```

### 6.3 AI가 하는 일과 하지 않는 일

| AI가 한다 | AI가 하지 않는다 |
| --- | --- |
| 이번 주 사건 제안(하린의 상태에 맞는 개인화) | 돈·능력·평판 수치 결정 (규칙 엔진 소관) |
| 사건·결과의 서술과 대사 연출 | 공식 Canon 변경 (규약 §4.3 — `ai` actor 쓰기 거부) |
| 핵심 인물과의 대화(Play CharacterChat) | 허용 목록 밖의 상태 전이 (코드 transition allowlist) |
| 한 달·한 시즌 회고 요약 | 인물이 알 수 없는 정보 사용 (`forbiddenKnowledge`) |
| 목표 재설정 갈림길에서 하린의 속마음 서술 | 안전 기준 밖 사건(§4.6) |

- **현행 코드 기준 제약** (이 브랜치 스냅샷 — 최신 코드 재확인 필요): Narrative Director는 `proposal-only`이고, `maxCallsPerSession: 1`, 프롬프트·출력 토큰 상한, 호출 전 가격표·잔액·예산 상한 게이트(`narrativeDirectorCostGate.ts`)를 거친다. 이 설계는 이 상한 안에서 동작하도록 **"한 주에 AI 사건 1건"**으로 잡았다. 나머지 결과는 규칙 엔진과 덱이 만든다.
- **AI가 막혀도 게임은 돈다.** 예산 상한·회로 차단·검증 실패 시 덱 이벤트로 대체한다. AI 모드의 fallback은 고정 루트가 아니라 **덱 기반 시뮬레이션**이다.
- **비용 고지**: AI 모드는 사용량에 따라 비용이 드는 모드임을 진입 전에 알린다(규약 §10 경제).

### 6.4 사용자별 결과와 공식 Canon

- AI 모드의 모든 결과는 **그 사용자의 Narrative Runtime**에만 남는다. 한 사용자의 하린이 브랜드를 접었다고 공식 하린이 접는 것은 아니다(규약 §4.2 Personal → Official Leak 금지).
- 많은 사용자가 같은 선택을 했다는 집계는 공식 루트 다음 시즌 기획의 **참고 자료**일 뿐, 자동으로 Canon이 되지 않는다.

## 7. Intelligence System — 지식이 선택지를 연다

### 7.1 원칙 (v1 유지)

1. 문제가 먼저, 지식은 나중. 아카이브는 미리 공부하는 곳이 아니라 **막힌 뒤에 답을 찾는 곳**이다.
2. 원천은 Magazine Knowledge Unit(읽기 전용) — `unitType · statement · mechanism · conditions · limitations · evidenceRefs` 그대로 투영.
3. 조건과 한계를 함께 보여준다. 성과 약속을 만들지 않는다.
4. Magazine으로 보내지 않는다. 출처 표시는 근거 표시일 뿐이다.
5. 근거 없는 지식은 카드가 되지 않는다.

### 7.2 v2 메커니즘 — 카드는 능력치가 아니라 선택지를 연다

| 방식 | 예 |
| --- | --- |
| **선택지 해금** | "만들기 전에 확인하기" 카드가 있으면 Ch9·P3에서 **사전 예약 테스트** 선택지가 보인다. 없으면 "크게 발표"와 "포기" 사이에서만 고른다 |
| **정보 공개** | "최소 주문 수량" 카드가 있으면 생산 화면에서 단가-수량-재고 위험 곡선이 보인다. 없으면 단가만 보인다 |
| **위험 신호 감지** | "좋은 기회와 사기를 가르는 신호" 카드가 있으면 수상한 에이전시 이벤트에 경고 표시가 뜬다 |
| **회고 연결** | 실패 이벤트 뒤 관련 카드가 아카이브에 "새 기록"으로 뜬다 — 겪은 뒤에 이해하게 한다 |

- 카드는 정답을 주지 않는다. **고를 수 있는 것을 늘릴 뿐**, 결과는 여전히 상황·능력·운에 달려 있다.

### 7.3 이미 준비된 Intelligence 원천 (이 브랜치에서 리뉴얼한 Magazine 기사)

| 기사 | 연결되는 게임 지점 |
| --- | --- |
| `content-persuasion-reach-vs-judgment-change` (도달 vs 설득) | 팔로워/신뢰도 분리 규칙(§3.5), Ch5·Ch6 |
| `ai-era-content-strategy-why-people-spend-time` (시간을 쓰는 콘텐츠) | 콘텐츠 제작 활동의 품질 규칙, Ch3·Ch5 |
| `ai-novel-writing-long-form-character-consistency` (장편 일관성) | 게임 규칙이 아니라 AI 모드 설계 근거(상태 외부 기록·생성/검증 분리) |

**아직 없는 Intelligence (기사 필요)**: 만들기 전에 수요 확인하기(Ch9) · 최소 주문 수량과 재고(Ch10) · 원가와 가격(Ch11) · 첫 계약서에서 볼 것(Ch4·Ch7) · 사기 신호(Ch2) · 현금흐름(P4).

## 8. Story(Home 인터랙티브 아티클)와의 관계

```text
공식 플레이(운영자, 공식 출발) ──(편집·승인)──▶ Home Story (ISCS 출판)
        │                                          │
        └── 출판 구간 = 모드 A 챕터                   └── 끝: "이 캐릭터로 나만의 스토리 시작하기"
                                                            → 이름 → 모드 A(공식 출발) / 모드 B(출발 목표 선택)
```

- Home Story는 **공식 플레이에서 편집·승인된 구간**만 다룬다. AI 모드의 개인 결과는 Story가 되지 않는다(사용자 생성 Story는 규약 §15 보류).
- Story 선택(`narrativeEffects`)은 사용자가 Play를 시작할 때 **시작 상태의 작은 차이**로 이어질 수 있다(예: Ch1 Story에서 "얼굴을 보여 준다"를 고른 사용자는 콘텐츠 능력이 조금 높은 상태로 시작). 연결 계약은 ISC-007 소관.
- Story에는 보상·코인·XP를 넣지 않는다(ISCS scope.out). Play의 경제·보상은 PWM 소관이다.
