## 1. 한 문장 정의

> **사용자는 멘토(the-world) 또는 지휘관(the-empire)이 되어, 각자의 꿈을 가진 캐릭터들을 이끌고 함께 경험하고 가르치며, 대결과 전투 같은 시험을 거쳐 그들이 성장해 가는 과정을 만드는 끝나지 않는 성장 시뮬레이션이다.**

| 요소 | 내용 |
| --- | --- |
| 사용자의 위치 | 주인공이 아니라 **이끄는 사람**. 캐릭터의 삶을 대신 사는 게 아니라, 캐릭터가 자기 목표에 닿도록 돕는다 |
| 캐릭터의 위치 | 각자 꿈·성격·의지를 가진 **독립된 사람(또는 존재)**. 사용자의 조언과 명령을 받아들이기도, 거절하기도 한다 |
| 성장의 원천 | 함께 하는 경험 · 사용자가 가져다주는 지식(Intelligence) · 대화 · **대결·전투라는 시험** |
| 끝 | 없다. 캐릭터는 계속 자라고, 실패하고, 목표를 바꾸고, 새 캐릭터가 합류한다 |

## 2. 유니버스별 시점

| | the-world | the-empire |
| --- | --- | --- |
| 세계 | 현대 도시 (인간형) | 판타지 제국 (몬스터형 포함) |
| 사용자 | **멘토** — 꿈을 가진 사람들의 길잡이 | **지휘관** — 부대를 이끄는 사령관 |
| 캐릭터 | 멘티 — 각자의 커리어·삶의 목표 | 부대원 — 각자의 사명·야망·생존 |
| 이끄는 방식 | 동행 · 정보 전달 · 대화 · 코칭 · 함께 짜는 계획 | 편성 · 훈련 · 작전 · 명령 · 사기 관리 |
| 시험 이벤트 | **대결** — 오디션·콘테스트·피칭·매출 경쟁 등 비폭력 경쟁 | **전투** — 부대 전투·결투·공성·방어 |
| 성장 결과 | 커리어 단계, 평판, 브랜드·사업 | 계급·칭호, 전투 능력, 부대 명성·영지 |

- 두 유니버스는 **같은 게임 골격**(로스터·성장·순환·시험 이벤트·두 모드)을 공유하고, 표현과 규칙 세부만 다르다.
- 캐릭터 타입은 유니버스 T0 규칙을 따른다(the-world = 인간형, the-empire = 몬스터형 포함). 코드에는 이미 `CHARACTER_SPECIES_IDS = ["human", "monster"]`가 있다.

## 3. 로스터 — 여러 캐릭터를 함께 키운다

### 3.1 구성

| 출처 | 설명 | 공식 Canon |
| --- | --- | --- |
| **공식 캐릭터** | 운영이 만든 캐릭터(예: the-world의 하린). 공식 이야기의 주인공 | 정의는 Canon, 사용자별 성장은 개인 진행 |
| **사용자 생성 캐릭터** | 기존 캐릭터 genesis 흐름(`IUserGameCharacterDoc`)으로 만든 캐릭터 | 개인. personal-universe 정책은 규약 §15 보류 범위 — 공개·Canon 연결은 별도 계약 |
| **합류 캐릭터** | 플레이 중 만난 인물이 조건을 만족하면 로스터에 합류(예: the-world의 지유·세라) | 정의는 Canon, 성장은 개인 진행 |

### 3.2 운영 규칙 (제안)

- **처음에는 1명**으로 시작한다. 첫 캐릭터와의 관계·순환을 익힌 뒤 로스터 칸이 늘어난다.
- 로스터 상한(예: the-world 3명 / the-empire 부대 6명 — 자리표시 값). 상한이 있어야 "누구에게 시간을 쓸지"가 선택이 된다.
- **사용자의 시간은 한정된 자원**이다. 한 주에 함께할 수 있는 칸이 정해져 있어, 한 캐릭터에 집중하면 다른 캐릭터는 스스로 지내고(자율 행동), 관계가 식을 수 있다.
- 캐릭터끼리도 관계가 생긴다. 같은 로스터의 두 캐릭터가 협력하거나 경쟁하고, 그 관계가 대결·전투의 변수가 된다.

## 4. 캐릭터 성장 모델

### 4.1 층

| 층 | 내용 | 코드 재사용 후보 |
| --- | --- | --- |
| **기본 속성** (유니버스 공통) | 활력 · 집중 · 통찰 · 공감 · 적응 · 행운 | `CHARACTER_GENESIS_ATTRIBUTE_OPTIONS` (6종) |
| **스킬** (유니버스별) | the-world: 모델링·스타일링·콘텐츠·소통·디자인·비즈니스·네트워크 / the-empire: 무기술·마법·전술·지휘·생존 등 | 신규 |
| **지식** | 사용자가 전해 준 Intelligence 카드 — 캐릭터가 **아는 것**(규약 §4.4) | Canon `allowedKnowledge` 개념 |
| **상태** | 컨디션·마음(사기)·현재 목표·감정 | 신규 (시뮬레이션 상태) |
| **관계** | 사용자와의 **신뢰**, 다른 캐릭터·NPC와의 관계 | `relation.affinity.adjust`, `npc-intimacy`(친밀도 정산 구조) |
| **경력** | the-world: 커리어 단계·평판 / the-empire: 계급·칭호·전공 | 신규 |

- 기본 속성은 **천천히** 오르고, 스킬은 활동과 시험으로 오르며, 지식은 사용자가 전해 줄 때 생긴다. 세 속도가 다르기 때문에 "무엇을 키울지"가 전략이 된다.
- 기존 genesis에는 희귀도 확률표(`CHARACTER_GENESIS_RARITY_DISCLOSURE`)가 있다. **성장 결과에는 확률형 등급·뽑기를 붙이지 않는다.** 성장은 선택과 경험의 결과여야 한다(경제·확률형 판정은 PWM·compliance 소관).

### 4.2 신뢰와 자율 — 이 게임의 핵심 규칙

캐릭터는 사용자의 조언·명령을 **판단해서** 따른다.

```text
수용 여부 = f(신뢰, 성격 적합도, 현재 상태, 조언의 근거)
```

| 요인 | 작용 |
| --- | --- |
| 신뢰 | 함께한 시간·지켜진 약속·조언이 맞았던 경험으로 쌓인다. 무리한 지시·거짓 정보·방치로 깎인다 |
| 성격 적합도 | 캐릭터의 가치·두려움과 맞는 조언은 쉽게 받아들이고, 정면으로 부딪히는 조언은 망설인다 |
| 현재 상태 | 지치거나 흔들리면 좋은 조언도 거절할 수 있다 |
| 조언의 근거 | **관련 Intelligence 카드를 함께 건네면** 설득력이 올라간다 — "그냥 해 봐"보다 "이런 기록이 있어"가 통한다 |

- 결과는 **수용 / 변형 수용 / 거절** 세 가지다. 거절에는 반드시 이유가 보인다("지금은 너무 지쳤어요", "그건 제 방식이 아니에요").
- 거절한 뒤의 결과도 캐릭터의 경험으로 남는다. 캐릭터가 자기 방식으로 실패하고 배우는 것도 성장이다.
- **성장할수록 자율이 커진다.** 초반에는 조언을 잘 따르지만, 성장할수록 스스로 판단하고 반대 의견을 낸다. 사용자의 역할은 안내자 → 조언자 → 동료·참모로 바뀐다(the-empire: 신병 → 정예 → 장교).
- **질문형 코칭 보너스**: 답을 바로 주는 것보다 질문으로 스스로 답을 찾게 했을 때 캐릭터의 성장(특히 통찰)이 더 크다. 훈계하는 플레이보다 이끄는 플레이가 유리하도록 한다.

## 5. 핵심 순환

### 5.1 한 주(the-world) / 한 작전 주기(the-empire)

```text
1. 상황 확인      캐릭터의 고민·목표·상태 / 부대 상황·정세
2. 계획          함께 짜는 주간 계획 — 사용자가 제안, 캐릭터가 조정·거절 가능
3. 동행·활동      장소를 함께 다니며 경험 (the-empire: 훈련·정찰·보급)
4. 정보 가져오기   아카이브에서 Intelligence 카드를 찾아 캐릭터에게 전달
5. 대화·코칭      Play CharacterChat — 조언·질문·격려 (the-empire: 작전 회의·명령)
6. 캐릭터의 결정   신뢰·성격·상태·근거에 따라 수용/변형/거절
7. 결과          규칙 엔진이 계산 → 스킬·평판·관계·상태 변화
8. 시험 이벤트     조건이 맞으면 대결/전투 발생 (§6)
9. 회고          캐릭터의 한 줄 일기 / 전투 보고 — 무엇을 배웠나
```

### 5.2 시간과 끝

- 시간은 계속 흐른다. 시즌·해가 바뀌고 캐릭터는 나이를 먹고 경력을 쌓는다.
- 게임 오버는 없다. 크게 실패한 캐릭터에게도 **회복 경로가 하나 이상** 있다. 캐릭터가 로스터를 떠나는 일(독립·이별)은 있을 수 있지만, 그것도 이야기의 한 결말이지 게임의 끝이 아니다.

## 6. 시험 이벤트 — 대결(the-world) · 전투(the-empire)

### 6.1 공통 구조

```text
준비 단계   훈련·편성·전략 선택, 지식 카드 장착(예: 상대 분석)
   ↓
진행 단계   라운드 진행 — 결과는 속성·스킬·상태·전략·상대·작은 운으로 결정
            사용자는 진행 중 1~2회 개입(코칭 한마디 / 지휘 명령). 캐릭터가 따를지는 신뢰에 달림
   ↓
결과 단계   승·패·무 + 항상 성장(패배에서 더 많이 배우는 스킬도 있음)
            평판·관계·다음 기회에 영향
   ↓
후속 사건   라이벌 관계, 스카우트, 부상·번아웃, 사기 변화
```

- **승패보다 성장이 크다.** 지는 것이 손해만은 아니도록 한다 — 실패 학습이 다음 시험의 선택지를 연다(규약의 "실패가 다음 장의 조건" 원칙).
- 결과 계산은 **결정적 규칙 엔진**이 한다. AI는 대결·전투의 연출과 대사만 맡는다(§7.3).
- 시험은 **조건으로 열린다**(실력·평판·초대·정세). 매주 강제로 오지 않는다. 사용자가 피하거나 미룰 수도 있고, 피한 대가도 있다.

### 6.2 the-world 대결 유형 (비폭력)

| 유형 | 겨루는 것 | 주로 쓰는 능력 |
| --- | --- | --- |
| 오디션 | 캐스팅 담당 앞에서의 워킹·포즈·면접 | 모델링·집중·공감 |
| 스타일링 배틀 | 주어진 예산·주제로 코디 완성 | 스타일링·통찰 |
| 콘텐츠 챌린지 | 같은 기간에 같은 주제로 콘텐츠 반응 경쟁 | 콘텐츠·소통 |
| 팝업 매출전 | 같은 날 같은 거리에서 판매 성과 | 비즈니스·공감·신뢰도 |
| 피칭 | 투자자·바이어 앞 브랜드 발표 | 비즈니스·통찰·소통 |

### 6.3 the-empire 전투 유형

| 유형 | 내용 |
| --- | --- |
| 결투 | 1:1 명예 대결 — 개인 능력·전술 선택 |
| 부대 전투 | 편성·진형·지휘 명령 — 캐릭터 간 관계·사기가 변수 |
| 방어전 | 거점 방어 — 준비 단계의 보급·훈련이 핵심 |
| 원정 | 여러 주기에 걸친 작전 — 보급·피로 관리 |

- 전투 묘사는 **전 연령 기준**(규약 §10 미성년 `pass` 조건)을 지킨다. 유혈·잔혹 묘사, 사망 연출의 직접 묘사를 하지 않는다. 쓰러진 캐릭터는 "전투 불능 → 회복"으로 다룬다. 공식 캐릭터의 영구 사망·퇴장은 규약 §4.3 승인 필수 변경이다.
- the-empire 세부(세력·지도·병종·전투 규칙)는 the-empire 설계 문서에서 정한다.

## 7. 두 플레이 모드 (유니버스 공통)

### 7.1 모드 A — 고정 루트 (AI 미사용)

- 공식 이야기의 출판된 구간을 따라간다. 조언·명령은 **선택지 카드 3개**에서 고른다. 캐릭터의 반응·결과는 작성된 결과표에서 나온다.
- 대결·전투도 규칙 엔진으로 돌아간다(AI 없이 완결).
- 비용이 들지 않고, 세계·인물·규칙을 소개하는 입구 역할을 한다.

### 7.2 모드 B — AI 시뮬레이션 (AI 사용)

- 대화가 자유롭다. 사용자는 말로 조언하고 질문하고 격려한다.
- 사건은 상태에서 생기고, AI가 개인화된 사건을 제안한다.
- 같은 캐릭터라도 사용자마다 전혀 다른 성장 경로가 나온다.

### 7.3 AI의 역할과 경계

| AI가 한다 | AI가 하지 않는다 |
| --- | --- |
| 캐릭터의 대사·반응 연출, CharacterChat | 수치(속성·스킬·평판·승패) 결정 — 규칙 엔진 소관 |
| 사용자의 조언이 어떤 성격의 조언인지 분류(질문형·지시형·근거 제시 등) → 규칙 엔진의 수용 계산 입력 | 수용 여부를 임의로 결정 |
| 주간 사건 제안(검증 후 채택) | 공식 Canon 변경(규약 §4.3) |
| 대결·전투 연출, 회고 일기 | 캐릭터가 모르는 정보 사용(`forbiddenKnowledge`) |

- 현행 Narrative Director 제약(이 브랜치 스냅샷 기준): `proposal-only`, `maxCallsPerSession: 1`, 비용 게이트. **대화 중심 게임이므로 CharacterChat 비용 정책을 별도로 정해야 한다**(§10 결정 3).
- AI가 막히면(예산·회로 차단·검증 실패) 덱 이벤트와 선택지 카드로 대체해 게임은 계속 돈다.

## 8. 공식 이야기·Home Story와의 관계

- **공식 이야기는 "공식 멘토(지휘관)가 이끈 기록"이다.** 운영자가 공식 캐릭터를 공식 출발 설정에서 이끌고(공식 플레이), 그 기록을 편집·승인해 Home Story로 연재한다. 출판 구간은 모드 A의 챕터가 된다.
- Home Story는 **캐릭터의 시점**으로 전개하고, 멘토는 "메시지를 보내는 누군가"로만 등장한다.
- **Story의 선택지 = 멘토가 해 줄 말.** "하린에게 뭐라고 말해 줄까?"처럼 쓴다. Story 시청자가 이미 멘토로 참여하는 구조라 Play로 넘어가는 동선이 자연스럽다. CTA: "하린의 멘토가 되어 주세요".
- Story 선택지에서도 캐릭터는 자기 판단을 한다. 시청자의 조언대로 되지 않는 결과도 쓸 수 있다(Story의 Immediate Result에 수용/거절 반영).
- Story에는 보상·코인·XP를 넣지 않는다(ISCS scope.out).

## 9. 경계 — Canon·안전·데이터

| 항목 | 기준 |
| --- | --- |
| Canon | 캐릭터 **정의**는 공식 Canon, 사용자별 **성장·관계·지식**은 개인 진행(규약 §4.2). 한 사용자의 결과가 공식 Canon이 되지 않는다 |
| 멘토 관계의 성격 | 멘토–멘티 / 지휘관–부대원으로 고정. **연애·독점·의존을 유도하는 관계 설계를 하지 않는다.** 캐릭터의 목표 달성이 화면의 중심이다 |
| 사용자 정체성 | 사용자는 **멘토(지휘관) 호칭**을 정한다. 캐릭터 이름은 공식 이름 그대로(이전 설계의 캐릭터 이름 변경은 폐기) |
| 대화 로그 | CharacterChat 로그는 compliance §4·§4-1 수집·고지 기준. 미확정이면 공개 `blocked`(규약 §10) |
| 전투·경쟁 묘사 | 전 연령 기준. 실존 인물·브랜드 없음 |
| 확률형 | 성장 결과에 뽑기·확률형 보상 없음. Play 경제 판정은 PWM |
| AI 생성 고지 | AI 대사·이미지 고지 |
| 비용 | AI 모드는 사용량 기반 비용임을 진입 전에 알린다 |
