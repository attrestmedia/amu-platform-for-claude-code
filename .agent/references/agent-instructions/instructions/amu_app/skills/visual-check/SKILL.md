# 시각적 검증 워크플로우 (WordPress Theme)

## 실행 조건

- WordPress 테마 UI 변경 작업 완료 후
- 메인 페이지/랜딩 섹션 수정 시
- 새로운 페이지 템플릿 추가 시

## 사전 요구사항

시각 검증은 **`visual-check` MCP 서버**를 통해 수행

- MCP 클라이언트에 `visual-check` 서버가 등록되어 있을 것
- 최초 1회는 MCP 서버 패키지 기준으로 Playwright Chromium 런타임이 준비되어 있을 것
- WordPress 로컬 또는 스테이징 서버가 실행 중일 것

## 실행 단계

### 1단계: 서버 준비 상태 확인

먼저 MCP의 `visual_doctor`를 호출해 브라우저 런타임과 preset 상태를 점검

```json
{
  "tool": "visual_doctor",
  "target": "amu-web-wordpress"
}
```

- `isError: true`이면 브라우저 런타임 또는 MCP 서버 설정 문제를 먼저 해결

### 2단계: 서버 상태 확인

```bash
curl -s -o /dev/null -w "%{http_code}" http://100.87.218.123/
```

### 3단계: MCP로 스크린샷 캡처

```json
{
  "tool": "capture_visual",
  "target": "amu-web-wordpress",
  "audit": true,
  "includeDark": false
}
```

스테이징/특정 포트를 직접 검증해야 하면 URL을 명시:

```json
{
  "tool": "capture_visual",
  "url": "http://100.87.218.123/slug",
  "audit": true,
  "includeDark": false
}
```

**출력 파일 (뷰포트 4종):** amu24는 현재 light-only이므로 dark 캡처를 요청하지 않는다.

- MCP 응답 텍스트에는 저장 경로와 audit JSON이 포함됨
- 기본적으로 hero 이미지 2장이 MCP `image` content로 함께 반환됨
- 추가 산출물은 `captureDir` 아래 PNG로 저장됨

### 4단계: `audit` 자동 검증 결과 확인

`capture_visual(..., audit=true)`는 아래 항목을 자동 검사

- 첫 뷰포트 내 헤딩/카드/CTA/이미지 개수
- 터치 타겟 미달 요소 (44x44px 미만)
- 경고 메시지 자동 생성

> **개수 자체를 실패 기준으로 쓰지 않는다.** audit의 카드·CTA 개수는 화면을 이해하기 위한 관측값이며,
> 편집면처럼 카드가 정상 구성 요소인 화면에서는 개수가 많은 것이 결함이 아니다.

### 5단계: 시각 분석 및 체크리스트 대조

MCP가 반환한 이미지와 저장된 PNG를 기준으로 아래 체크리스트를 시각적으로 확인:

**모든 화면 공통**

- [ ] **모바일 레이아웃**: 375px에서 가로 overflow 없이 렌더링되는가?
- [ ] **반응형**: 375 / 768 / 1024 / 1440px에서 레이아웃이 깨지지 않는가?
- [ ] **터치 타겟**: 인터랙티브 요소가 최소 44x44px인가?
- [ ] **키보드**: Tab 순서가 자연스럽고 focus ring이 보이는가?
- [ ] **색상 모드**: light에서 정상인가? (amu24는 현재 light-only — dark 통과를 주장하지 않는다)
- [ ] **reduced-motion**: 이동·burst 효과가 제거되고 상태 변화는 유지되는가?
- [ ] **CLS**: 이미지 예약 공간이 있어 로드 중 레이아웃이 밀리지 않는가?
- [ ] **브랜드 테스트**: 내비게이션을 가려도 AMU 브랜드로 식별 가능한가?
- [ ] **화면 초점**: "이 화면의 주인공이 무엇인가"에 한 가지로 답할 수 있는가?
- [ ] **섹션 단일 목적**: 각 섹션이 하나의 역할만 수행하는가?
- [ ] **AI 슬롭 없음**: 예측 가능한 나열형 레이아웃, 목적 없는 보라·분홍 그라데이션, 근거 없는 통계 배지가 없는가?

**이미지가 있는 화면**

- [ ] **비율 존중**: 원본 비율이 유지되고 강제 crop이 없는가?
- [ ] **오버레이 대비**: 이미지 위 텍스트·라벨·배지가 대비를 확보했고 정보가 가려지지 않는가?
- [ ] **맥락 있는 비주얼**: 주인공 이미지가 장식적 추상 배경이 아닌가?

**서비스 소개·랜딩 성격의 페이지에만**

- [ ] **전환 흐름**: 정체성 → 맥락 → 설명 → 신뢰 → 전환 순서가 성립하는가?
- [ ] **CTA 집중**: Primary CTA가 하나로 읽히는가?

> 편집면(매거진 홈 · 아카이브 · 기사)에는 위 랜딩 항목을 적용하지 않는다.
> 편집면의 카드 · 카테고리 칩 · 읽기 시간 · 관계 상태 타일 · 액션 레일은 **정상 구성 요소이며 실패 사유가 아니다.**

### 6단계: 문제 발견 시

- 각 문제에 대해 수정 패치를 제안 (최소 diff 형식)
- CSS/JS 변경은 영향 범위(레이아웃/성능/SEO/접근성)를 3~6줄로 요약 후 적용
- `capture_visual`을 다시 호출하여 재검증

## 참고

- MCP 서버 이름: `visual-check`
- 주요 도구:
  - `visual_doctor`
  - `capture_visual`
- 이 스킬은 프론트엔드 디자인 하드 룰(`{{AGENT_ROOT}}/rules/wp-theme-ui.md`)을 기반으로 검증
- WP 테마 수정 시 기존 테마 구조/헬퍼를 먼저 찾고 재사용 — 무단 구조 변경 금지
