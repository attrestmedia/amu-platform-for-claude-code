# 미니앱 구현 규칙

## 1. 미니앱의 정의

미니앱은 **범위를 극단적으로 좁힌 단일 목적 앱**이다. 검색으로 유입되어 첫 세션 안에 하나의 결과를 얻고, 필요하면 본 서비스로 이어지는 퍼널이자 랜딩(SSR/SEO) 역할을 한다.

**형식은 제한하지 않는다.** 도구·유틸리티, 정보 조회, 진단·추천, 캐주얼 게임 모두 미니앱이다.
판정 기준은 형식이 아니라 아래 셋이다.

1. 목적이 하나로 좁혀져 있는가
2. 첫 세션 안에 결과 하나를 손에 쥐는가
3. 검색 유입이 가능한 주제인가

> **개정 이력(2026-08-13).** 이전 규칙은 "게임성과 재미를 극대화한 캐주얼 게임 형식"을 **필수**로 요구했다.
> 실측 결과 운영 중인 미니앱 6종(`catalog` · `drawing` · `motion-studio` ·
> `school-lunch-food-map` · `scrape-links` · `search-imgs`) 가운데 캐주얼 게임은 **0종**이고 전부 도구·정보형이다.
> 규칙이 구현 현실과 어긋난 상태였으므로 유형을 넓히고, 게임 전용 요건을 유형별 조건부로 옮겼다.

## 2. 유형과 성공 기준

착수 전에 **유형을 하나 선언한다.** 선언한 유형의 요건만 적용하고, 다른 유형의 요건을 억지로 끌어오지 않는다.

| 유형 | 설명 | 실제 예 | 성공 기준 |
| --- | --- | --- | --- |
| `tool` | 입력을 받아 결과물을 만들거나 가공한다 | `drawing`, `motion-studio` | 결과물 완성률, 저장·다운로드율 |
| `utility` | 흩어진 작업을 한 화면에서 끝낸다 | `search-imgs`, `scrape-links` | 작업 완료율, 재사용률 |
| `info` | 특정 정보를 빠르게 조회·탐색한다 | `school-lunch-food-map`, `catalog` | 조회 성공률, 재방문 |
| `advisor` | 입력을 받아 진단·추천·계산 결과를 준다 | — | 결과 도달률, 결과 공유·저장률 |
| `game` | 놀이 자체가 목적이다 | — | 플레이 완료율, 재플레이율, 공유율 |

- 한 앱이 두 유형에 걸치면 **주 유형 하나를 정하고** 나머지는 부가 요소로 둔다.
- 유형은 앱 메타에 기록하고 계측 이벤트에 함께 싣는다.

## 3. 공통 필수 요건 (유형 무관)

- **랜딩 + 본체 2단 구조**를 유지한다. 랜딩은 SSR/SEO 대상이며 자연 검색 유입을 설계한다.
- **초협소 타겟팅** — 특정 사용자층과 특정 문제로 범위를 좁힌다. 범용 도구를 만들지 않는다.
- **3초 가치 전달** — 첫 폴드에서 무엇을 얻는지 이해되어야 하고, 실제 결과물·데모 등 품질을 증명하는 시각 요소를 포함한다.
- **첫 세션 성과** — 첫 세션 안에 결과물 1개 또는 핵심 행동 1회를 완료할 수 있어야 한다.
- **가이드 없는 사용성** — 별도 설명 없이 즉시 이해되는 단순 UI.
- **플랫폼 자산 재사용** — 공통 UI, 코인 결제, AI API 등 기존 구현을 우선 사용한다.
- **모바일 퍼스트 + `_tokens.scss` 기반 light/dark** 테마 필수.
- **아토믹 디자인 기반 재사용 설계** — 미니앱 전용 컴포넌트도 다른 미니앱에서 쓸 수 있게 만든다.
- **공통 컴포넌트와 lucide 아이콘 우선** (emoji 사용 금지).
- **히어로 예산** — 랜딩 첫 뷰포트는 앱 이름 + 한 줄 가치 제안 + CTA 1개 + 데모/결과물 1개로 제한한다. 기능 목록·가격·부가 설명은 아래 섹션으로 분리한다.
- **카드 UI는 결과물 표시·인터랙션 컨테이너로만** 쓴다. 레이아웃 구분용 카드 남발 금지, 히어로에 카드 금지.
- **AI 기능 고지** — AI 이미지 생성·챗 연동 시 로그인/코인 충전 필요 문구를 랜딩 또는 본체에 최소 1회 노출한다.
- **비용 발생 액션의 가치 체감** — 유료 액션이 가치 확인을 전면 차단하지 않게 하고, 무료 구간 또는 결과 예시를 먼저 제시한다.
- **기획 입력** — WordPress 글(`GET /api/thirdparty/wp/posts`) 또는 키워드·아이디어를 사용한다. 참고 자료의 팁·체크리스트·가이드를 활용해 사용자의 다음 행동을 설계한다.
- 완성 후 `visual-check`로 시각 품질 검증 실행을 권장한다.

## 4. 유형별 조건부 요건

**아래는 해당 유형에만 적용한다. 다른 유형에 끌어와 강제하지 않는다.**

| 요건 | 적용 유형 | 내용 |
| --- | --- | --- |
| 게임성·재미 극대화 | `game` | 놀이 자체가 목적인 앱에만 요구한다. 규칙이 단순하고 즉시 이해되며 실패해도 다시 하고 싶어야 한다 |
| 반복 루프 | 재방문을 목표로 하는 앱 | Daily/Weekly mission, streak, score, collection, ranking, personalized recommendation, social reaction path 중 최소 1개. **재방문이 목표가 아닌 앱에는 요구하지 않는다** |
| 공유 요소 | 결과물이 남는 앱(`tool`·`advisor`·`game`) | 결과 화면에 공유 가능한 요약 카드 또는 전달 포맷을 둔다 |
| 결과 활용 안내 | `tool`·`advisor` | 추천 사용처, 대체 옵션, 저장·개인화 등 다음 행동을 함께 제시한다 |
| 정확성·출처 표기 | `info`·`advisor` | 데이터 출처와 기준 시점을 밝힌다. 추정값은 추정이라고 쓴다 |
| 개성적 인터랙션 | 전 유형 | 공통 레이아웃·모듈 구조는 유지하되 앱의 성격에 맞는 고유 인터랙션을 더한다 |

## 5. 금지

- **억지 게이미피케이션 금지.** 도구·유틸·정보형 앱에 목적 없는 streak·점수·랭킹을 붙이지 않는다. 반복 루프는 재방문이 실제 목표일 때만 설계한다.
- **형식을 이유로 반려하지 않는다.** "게임이 아니라서" 또는 "재미 요소가 없어서"는 미니앱 제안의 반려 사유가 아니다. §1의 세 기준으로 판정한다.
- 범용 도구화 금지 — 기능을 늘려 범위를 넓히는 방향으로 확장하지 않는다.
- 측정 불가능한 플로우를 기본안으로 채택하지 않는다.

## 6. 계측

**공통 이벤트**(전 유형): `landing_view`, `start_click`, `step_completed`, `return_visit`

**조건부 이벤트**

| 이벤트 | 적용 |
| --- | --- |
| `assist_generate_click` / `assist_generate_success` | AI 텍스트 보조를 쓰는 앱 |
| `image_generate_click` / `image_generate_success` | AI 이미지 생성을 쓰는 앱 |
| `share_click` | 공유 요소가 있는 앱 |
| `result_download` / `result_save` | 결과물이 남는 앱(`tool`·`utility`) |
| `search_performed` / `lookup_success` | `info`·`utility` |
| `play_complete` / `replay_click` | `game` |

- 이벤트 파라미터에 앱 `type`을 함께 싣는다.
- 설계 단계에서 필수 이벤트와 KPI를 먼저 정의한다.
