# AMU "미니앱/미니게임" 제작 워크플로우

## 개요

- "미니앱"은 AMU 플랫폼(`app.allmyuniverse.com`)에서 제공되는 **극단적으로 타게팅된 주제**를 위한 소규모 애플리케이션
- "미니앱"은 트래픽을 본 서비스로 유입시키는 퍼널로서 **`랜딩 페이지` + `앱 본체`** 의 2단 구조로 구현
- **형식은 제한하지 않는다** — 도구·유틸리티, 정보 조회, 진단·추천, 캐주얼 게임 모두 미니앱이다. 착수 전에 유형을 하나 선언하고 그 유형의 요건만 적용한다
  > 유형 정의와 유형별 조건부 요건은 `{{AGENT_ROOT}}/rules/mini-app.md` §2·§4가 정본이다. 이 문서에 유형 요건을 복제하지 않는다
  > 게임성·재미는 `game` 유형의 최우선 기준이며, 도구·유틸·정보형에 억지로 요구하지 않는다

## 핵심 원칙

1. **플랫폼 자산 최대 활용** — 코인 결제 · AI 콘텐츠 생성 · AI 챗 · 공통 UI 라이브러리 등 기존 구현을 재사용
2. **초협소 타겟팅** — 문제/사용자 범위를 좁혀 검색 유입과 전환을 설계
3. **가이드 없는 사용성** — 별도 설명 없이 즉시 이해 가능한 단순 UX
4. **모바일 + 테마 일관성** — 모바일 UX를 최우선으로 설계하고, `_tokens.scss`를 기준으로 light/dark 모두 지원
5. **AI 기능 고지 의무** — AI 이미지/챗 기능은 로그인/코인 충전 필요 문구를 반드시 노출
6. **컴포넌트 재사용성** — "미니앱/미니게임"의 모든 구성 요소는 다른 앱에서도 활용할 수 있도록 "아토믹 디자인"에 기반한 공통 설계 적용
7. **아이디어 입력** — 미니 앱의 아이디어는 allmyuniverse 사이트의 기사 또는 키워드, 아이디어 설명 등으로 제시
   > WordPress의 글로 제공시 API로 해당 글의 내용을 검토하여 주제에 맞는 '미니 앱 설계 가이드'를 제시
   > 참고 자료의 유용한 팁, 체크리스트, 가이드 등을 모두 활용하여 사용자의 행동을 유도할 수 있는 장치를 치밀하게 설계
8. **첫 화면 증명** — 첫 폴드에서 3초 안에 가치 제안이 이해되어야 하며, 실제 결과물/서비스 퀄리티를 증명하는 샘플 이미지·데모·슬라이드·masonry 레이아웃 중 최소 1개 이상 포함
9. **첫 세션 성과** — 첫 세션 안에 사용자가 결과물 1개를 얻거나 핵심 행동 1회를 완료하도록 설계
10. **반복 루프 설계** — 재방문을 목표로 하는 앱은 Daily/Weekly mission, streak, score, collection, ranking, personalized recommendation, social reaction path 중 최소 1개 이상 포함
11. **실무 전달력** — 결과 화면은 생성 결과만 보여주지 말고 사용처, 대체 카피, 공유 카드, 다음 액션 등 즉시 활용 가능한 전달 단위를 함께 제공
12. **데이터 우선 개선** — 설계 단계에서 필수 이벤트와 KPI를 먼저 정의하고, 측정이 불가능한 플로우는 기본안으로 채택하지 않음

## 1단계: 랜딩 페이지

### 목적

검색/SNS 유입 → AMU 플랫폼 가입/앱 진입으로의 **전환율 극대화**

### 필수 요소

- **히어로 섹션**: 한 줄 헤드라인 + 서브카피 + CTA 버튼, 그리고 첫 폴드 내 3초 가치 제안
- **실제 결과물 증명**: 샘플 이미지, 전후 비교, 카드 묶음, 슬라이드, masonry 등으로 "결과 품질" 또는 "서비스 결과"를 즉시 증명
- **인터랙티브 데모**: 앱의 핵심 기능을 체험할 수 있는 매력적인 인터랙션/UI 제공(스크롤 애니메이션, 라이브 프리뷰 등)
- **미니앱/미니게임의 소구 포인트 노출**: 반드시 해당 미니앱/미니게임의 특징과 재미/마케팅 포인트를 날카로운 핵심 아이디어로 표현
- **소셜 프루프**: 사용자 수, 리뷰, 생성 결과물 갤러리 등
- **SEO 최적화**: 구조화 데이터(JSON-LD), 메타 태그, OG 이미지
- **AI 기능 고지**: 프로젝트에 구현된 AI 기능 활용 시 `로그인 및 코인 충전 필요 문구`를 CTA 근처에 노출

### 인터랙션 규칙

- CSS 애니메이션을 우선 사용하고, 복잡한 경우에만 `framer-motion`/`gsap` 도입
- 스크롤 기반 시차(Parallax) 효과로 깊이감 부여
- 로딩/전환 시 **마이크로 인터랙션**으로 체감 속도 향상
- **AI 슬롭 회피**: 흰 배경 + 보라 그라데이션 같은 진부한 패턴을 피하고, 앱 주제에 맞는 개성 있는 색 구성 사용

## 2단계: 앱 본체

### 설계 철학

> Apple UI의 **"단순함"** 과 **"아름다움"** 을 지향 — 사용자가 고민 없이 자연스럽게 사용할 수 있는 UX

### 구조

```
app/(apps)/[app-slug]/
├── page.tsx          ← 랜딩 + 앱 페이지 (SSR/SEO)
├── components/       ← 앱 전용 컴포넌트
├── hooks/            ← 앱 전용 훅
└── lib/              ← 앱 전용 유틸
```

### 필수 구현 사항

- **i18n 적용**: 모든 사용자 노출 텍스트에 `<Lang>` / `lang()` 사용
- **첫 세션 완료 설계**: 첫 진입 후 한 세션 안에 결과물 1개 또는 핵심 행동 1회를 반드시 완료할 수 있는 기본 플로우 제공
- **코인 결제 연동**: AI API 호출 시 기존 코인 차감 시스템 활용
- **인증/결제 고지**: "로그인/코인 충전 후 사용 가능" 문구를 최초 진입 화면에 표시
- **테마 적용**: `_tokens.scss` 기반 light/dark 테마를 모두 지원
- **에러/로딩 상태**: 스켈레톤 UI + 토스트 알림으로 자연스러운 피드백
- **결과물 공유**: 생성된 콘텐츠를 SNS/링크로 공유 가능하게 구현하고, 결과 요약 카드 또는 공유 포맷을 함께 설계 (바이럴 유도)
- **실사용 가이드**: 결과 화면에 추천 사용처, 대체 카피/옵션, 주의점 또는 다음 액션 중 최소 1개 이상 제공

## 2-1단계: 반복 루프 기본값

재방문형 미니앱은 아래 장치 중 최소 1개 이상을 기본 설계에 포함한다.

- **Daily/Weekly mission**: 짧고 명확한 도전 제공
- **Streak/Score**: 누적/연속 사용 동기 부여
- **Collection/Unlock**: 수집/해금 기반 축적 구조
- **Ranking/Comparison**: 순위/비교/주간 베스트
- **Personalized recommendation**: 사용자별 새로움과 소유감 제공
- **Social reaction path**: 공유, 칭찬, 챌린지, 북마크 등 타인의 반응 경로

## 2-2단계: 데이터/실험 기본값

설계 또는 패치 제안에는 아래 이벤트와 KPI를 기본 포함한다.

### 필수 이벤트

- `landing_view`
- `start_click`
- `step_completed` (step 이름 포함)
- `assist_generate_click`
- `assist_generate_success`
- `image_generate_click`
- `image_generate_success`
- `share_click`
- `return_visit` (`D1`, `D7`)

### 핵심 KPI

- **Activation**: 첫 생성 완료율
- **Engagement**: 세션당 생성 횟수, 공유율
- **Retention**: `D1`, `D7`
- **Revenue**: 유료 전환율, 사용자당 코인 소모량

## 3단계: 콘텐츠 연계

"미니앱/미니게임"은 WordPress 글 또는 키워드와 연계하여 제작 가능

### 콘텐츠 → 미니앱 전환 흐름

1. **slug/키워드 입력 확정**
2. **핵심 메시지 추출**: 문제, 대상, 기대 결과를 1~2문장으로 압축
3. **랜딩 카피/앱 플로우 설계**: 유입→체험→전환 흐름 고정
4. **앱 제작**: 기존 플랫폼 기능 재사용으로 구현
5. **상호 링크**: 콘텐츠 ↔ 미니앱 CTA 교차 배치

## 4단계: 창의적 아이디어 도출

미니앱 기획 시 **일반적이고 안전한 아이디어를 피하고** 아래의 사고법 활용

### 권장 사고 프레임워크 (2개 이상 혼합 적용)

- **천재적 통찰(GI)**: 관찰→연결→패턴→종합, 고정관념/편향 최소화
- **창의적 연결(CC)**: 두 개념의 공통점·차이점·전이를 탐색하여 새로운 조합 발견
- **문제 재정의(PR)**: 반대 관점, 확대/축소, 상위/하위 개념 이동으로 문제를 다르게 정의
- **혁신적 솔루션(IS)**: 실현 가능성과 가치를 극대화하면서 리스크를 최소화
- **직관적 도약(IL)**: 논리적 제약을 줄이고 경험과 직관을 통한 비약적 발상

### 아이디어 검증 체크리스트

- [ ] 기존에 흔한 앱이 아닌가? (차별점 확인)
- [ ] 사용자에게 실질적 유용함을 제공하는가?
- [ ] 재미/흥미 요소가 명확한가?
- [ ] AMU 플랫폼의 강점(코인 결제, 멀티 AI)을 살리는가?
- [ ] 바이럴/공유 가능한 결과물이 나오는가?

## 기술 스택 참고

- **프레임워크**: Next.js 15+ (App Router) + React 19 + TypeScript
- **스타일**: Tailwind CSS 우선, 필요 시 SCSS 추가
- **상태관리**: Zustand (전역), React Query (서버 상태)
- **AI 연동**: 기존 코인 차감 API + OpenAI/Claude/Gemini 통합 인터페이스
- **애니메이션**: CSS 우선 → framer-motion → gsap (복잡도 순)
- **2D 그래픽**: PixiJS (게임/인터랙티브 요소)
- 새 의존성 추가는 기본적으로 지양해야 하지만, 불가피한 경우 **근거/대안/영향 범위**를 제시 후 승인 요청할 것
