# Social Content (Reference-first)

## 핵심 규칙

- 게시용 콘텐츠는 반드시 “소스 링크/슬러그/제목”에서 시작
- 자동화된 marketing-ops 로컬 에이전트 작업에서는 `source.outline/sourceQuotes/keyTerms/allowedClaims`를 먼저 근거로 선택한 뒤 작성
- `excerptText` 또는 에이전트가 자체 생성한 중간 요약만으로 게시용 본문 작성 금지
- 소스가 없으면: 게시용 본문을 쓰지 않고, 후보 소스 3개를 제시하고 선택을 요청
- WP/네이버 원문을 복사하지 않고, 채널별 독자 관점으로 재구성
- CTA는 1개만, 본문 링크는 1개만(나머지는 프로필/댓글)
  - "amu magazine"의 기사는 "draft" 상태라도 해당 글의 제목과 url을 CTA에 적용할 것
- 인스타그램은 조건 충족 시에만 옵션으로 제시
- 소셜 콘텐츠에는 항상 독자를 위한 유용한 정보, 팁 등을 포함
- marketing-ops MCP를 사용할 수 있는 환경에서는 작성 전 `get_social_performance`(최근 30일, quota 미소비)로 채널별 반응률/상위 게시물을 확인하고, 상위 성과 게시물의 주제/훅/형식을 채널별 앵글에 반영(저장된 스냅샷이 없으면 생략 — 작업 차단 아님, 임의 수치 인용 금지)
- marketing-ops 로컬 생성에서는 `prepare_local_generation.contentFitStrategies`를 `{{AGENT_ROOT}}/refs/marketing-guide/*`와 함께 채널별 `marketingFit`/`adFit` 기준으로 사용하고, `fitStrategiesError`가 있을 때만 `get_content_fit_strategies`를 1회 호출
- 모든 채널 산출물의 어미는 친근한 존대어로 통일(네이버/스레드=해요체, 링크드인=습니다체). 반말·평어 종결 금지 — `{{AGENT_ROOT}}/refs/content-policy/social_media_tone.md`의 "어미·존댓말 통일 규칙" 적용
- 강한 문제 제기·감정적 확대·도발적 질문·극적 대비·실패담을 적극 허용하되, 실제 경험·확인된 문제·합리적 의견에 기반하고 본문에서 훅의 약속에 답하게 작성 — `{{AGENT_ROOT}}/refs/content-policy/social_media_tone.md`의 "강한 표현 허용선" 적용

## 입력(요청 시 반드시 받기)

- 소스 유형(1개 선택):
  - WP 글 URL/slug
  - Gen Studio 기능/프리셋/템플릿/업데이트 메모 (+가능하면 템플릿 딥링크)
  - (선택된) 네이버 글 URL
- 콘텐츠 분류: Layer 1(매거진 기사) | Layer 2(도구·운영 소재)
- R 등급(필수 판정): R0 관계 | R1 확장(기사 맥락 성립) | R2 확장 간접 | R3 브랜딩 | R4 일반 — 판정 기준은 `.agent/amu-platform-guide/MARKETING-STRATEGY.md`의 "R Routing" 절
- 목표 행동(Primary, 1개만): 매거진 기사 저장·주제 팔로우·뉴스레터 구독 등 **관계 행동** | 기사 맥락의 확장 경험 실행 | 매거진 재방문
  > **모든 소재에 같은 서비스 CTA를 붙이지 않는다.** 확장 CTA는 기사 맥락을 반드시 동반하고, 관계 CTA와 함께 쓰지 않는다(1 CTA).

## 작업 순서

1. 소스에서 핵심 3줄 요약(문제/핵심 주장/즉시 행동) 추출
2. 타겟 독자 1명을 고정
3. (가능한 경우) 저장된 소셜 성과 스냅샷에서 채널별 반응률/상위 게시물을 확인해 앵글/훅/CTA 선택에 반영
4. 등록 전략 기준으로 채널별 Pre-Fit을 수행하고 Naver Blog는 블로그 목표/전략 주제 하드 게이트를 적용
5. 적합 채널별 앵글을 별도 설정(같은 얘기 반복 금지)
6. 네이버 블로그(롱폼) + 링크드인(인사이트) + 스레드(압축/시리즈)를 작성. Naver 부적합이면 본문 대신 exclusion marker를 제출
7. 각 validation에 `channelFit`, `marketingFit`, `adFit`, 전략 버전을 포함
8. 로컬 MCP 제출 후 `get_job(view="completion")`에서 서버의 독립 오탈자 검수(`google/gemini-3.5-flash-lite`) 결과와 최신 draft/validation 연결을 확인. 실패·미실행·stale이면 로컬 MCP 작업의 완료/발행 금지. 새 finding은 전체 유니버스 공통 오탈자 사전에 기록하고 콘텐츠 수정 후 재제출. `unavailable`이고 finding이 없으면 동일 초안 재제출이나 근거 없는 문장부호 변경 금지
8. 후속 바리에이션 3개(빌드업) 아이디어 추가
9. QA 체크 통과

## 채널별 출력 규격

### 네이버 블로그

- 제목 후보 3개(A/B/C)
- H2 3~6개 구조
- 체크리스트 1개
- 마지막 질문 1개
- CTA 1개

### 링크드인

- 첫 줄 훅 3개 중 1개 선택
- 번호 리스트 3~5개
- 마지막 질문 1개

### 스레드

- 단독(150~300자) 또는 1/5 시리즈
- 시리즈는 각 조각이 독립적으로 저장 가치가 있어야 함
- 줄바꿈 규격 적용: 줄 40자 이하, 문단 1~2줄(사이에 빈 줄 1개), 나열·숫자 쉼표는 줄 중간 유지 — `{{AGENT_ROOT}}/refs/content-policy/social_media_tone.md`의 "줄바꿈 규격"
- 해시태그는 별도 `hashtags` 필드에만 넣고 본문·제목·CTA·자답글에는 넣지 않는다. 본문에 해시태그 토큰이 있으면 제출 전 수정한다.

### (옵션) 인스타그램

아래 조건 중 1개라도 충족하면 “카드뉴스 구성(5~7장)”만 제시:

- Gen Studio 생성 이미지 자산/샘플이 제공됨
- 전후 비교/튜토리얼 성격
- 체크리스트/프레임워크가 카드로 분해 가능
