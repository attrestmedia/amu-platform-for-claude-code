# Compliance Guardrails (규제/컴플라이언스 가드레일)

## 목적

게임 경제·거래·가상자산·미성년/음성 데이터 등 규제 민감 기능이 코드 리뷰나 출시 직전이 아니라
**착수 전에** 규제 게이트를 통과하도록 체크리스트를 고정한다.
아래 영역에 해당하는 기능은 각 항목의 "착수 전 확정 계약"이 확정되기 전에는 구현 제안을 진행하지 않는다.

## 1. 환전/사행성 (게임산업법)

- **역방향 환전 금지**: 게임 내 재화·아이템을 현금성 가치로 되돌리는 경로를 만들지 않는다 (유상 → 무상 단방향만 허용).
- **확률형 보상은 확률 공시 전제**: 확률형 아이템/보상을 도입하는 기능은 확률 공시 UI/문서를 함께 설계한다.
- **유상 재화 소각처 선설계**: 유상 재화가 무한 축적되지 않도록 소비/소각 경로를 경제 설계 단계에서 확정한다.
- 관련 엔지니어링 계약: node-app `rules/server-economy-security.md` (이원 원장·에스크로).

## 2. 가상자산 (가상자산이용자보호법)

- AMU 자체 암호화폐/토큰 발행 구상은 **법률 자문 전 착수 금지** — 현재 상태는 "보류"로 고정한다.
- 포인트/코인이 "이전 가능 + 현금성 교환 가능" 두 조건을 동시에 충족하게 되는 설계 변경은 가상자산 규제 검토 대상이므로 사전 플래그를 올린다.

## 3. 개인정보 (음성·대화 데이터)

- 음성 원음 저장 기능(Tutors 등)은 **동의 절차 + 보존 TTL + 삭제 정책이 선행 확정**되어야 착수 가능 (정식 출시 전 필수).
- 미성년 관련 판정은 §3-1을 따른다.

## 3-1. 미성년 게이트 — 현행 판정 `pass` (2026-09-23 개정)

근거: `.agent/references/AMU_APP/in_progress/Minors_Regulation_Scandal.md`.
2026-09-23 사용자 결정 — 로드맵의 미성년 규제 게이트는 전부 `pass`로 처리하고, 실제 연령·본인 확인은 필요해지는 시점에 구현한다.
미성년 게이트가 주요 기능 로드맵을 반복적으로 지연시킨 것이 개정 사유다.

- **미성년 사유로 착수·공개를 막지 않는다.** 미성년 접근 가능성, 연령 미확인(unknown), 보호자 동의 부재, 연령대별 모더레이션 미설계는 `blocked` 사유가 아니다. 판정은 `pass`로 적고 근거로 이 절을 인용한다.
- **설계 원칙(게이트 아님)**: AMU는 전 연령에 안전한 콘텐츠를 지향한다. 대화형·생성형 기능은 연령과 무관한 공통 안전 기준을 따르고, 기존 모더레이션 자산(금칙·신고·차단)이 있으면 재사용한다. 연령대별 분기 설계는 요구하지 않는다.
- **참조 설계(구현 보류) — AMU Age Policy v1**: 만 14세 이상 서비스, 연령대 자율 신고(`ageBand` — 생년월일 미저장), 만 14세 미만 차단, 14~18세 minor safety 적용, 필요한 기능에만 step-up 인증. 아래 트리거가 생기면 이 설계를 출발점으로 구현한다. 상세는 근거 문서.
- **구현 트리거** — 발생하면 **해당 기능에 한해** 미성년 게이트를 다시 열고, 연령 확인을 구현하기 전에는 그 기능을 공개하지 않는다.
  1. 청소년유해매체물 또는 성인 전용 기능 도입 — 청소년보호법 §16은 나이와 본인 여부 확인을 요구하므로 자율 신고로 대체할 수 없다.
  2. 만 14세 미만을 대상으로 한 기능·마케팅 결정, 또는 만 14세 미만 이용 사실을 인지한 경우 — 개인정보보호법상 법정대리인 동의 의무.
  3. 외부 프로바이더 약관·계약이 이용자 연령 확인을 요구하는 경우 (예: ElevenLabs Grant `verified_adult`).
  4. 한국 외 국가를 대상으로 한 서비스 (COPPA 등 국가별 기준).
  5. 규제 당국의 지적·민원·안전 사고.
- **이 `pass`가 해소하지 않는 것** — 미성년 게이트가 아니므로 기존 기준을 유지한다: §3 음성 원음 동의·TTL·삭제, §4·§4-1 수집 항목·고지·동의(대화 로그 저장 포함), 프로바이더 계약상 연령 조건(트리거 3), 예산·품질 게이트. 게이트 하나에 미성년 조건과 다른 조건이 섞여 있으면 **미성년 부분만 `pass`로 떼어 내고** 나머지는 그대로 판정한다.
- **잔여 리스크(사용자 수용, 2026-09-23)**: 만 14세 미만 개인정보 처리에 대한 사업자 의무는 약관 문구나 자율 신고로 이용자에게 넘어가지 않는다. 연령 확인 없이 운영하는 동안 이 리스크를 수용한 상태다. 이용약관에 최소 이용 연령(만 14세)을 명시하는 것은 비용이 낮은 완화 수단으로 권장하지만 게이트 조건은 아니다 — 진행 시 `legal-policy-review` 스킬로 처리한다.

## 4. 고지 문서 정합 (개인정보처리방침 · 이용약관)

- `allmyuniverse.com`과 `app.allmyuniverse.com`이 공통 사용하는 고지 문서의 **정본은 `.agent/legal/policies/`**이며
  WordPress 페이지는 산출물이다. WP 관리자 화면에서 직접 수정하지 않는다.
- 아래 변경은 **정책 갱신 트리거**다. 구현과 같은 작업 단위에서 `legal-policy-review` 스킬로 검토한다.
  - 새 외부 프로바이더(AI·결제·분석·저장소·알림·**이메일 발송**) 자격증명 추가 — `consts/secure/platformCredentials.ts`
  - `UserSchema` 등 이용자 스키마의 수집 항목 추가
  - OAuth 권한 범위 확대 — **매거진 소셜 로그인 추가를 포함한다**
  - 보유기간·파기 정책 변경

## 4-1. 독자 관계 데이터 (2026-08-06 신설)

매거진 중심 사업 전환으로 **회원 행동 데이터를 수집·결합·활용하는 기능**이 대거 신설된다.
아래는 전부 §4의 정책 갱신 트리거이며, **구현과 같은 작업 단위에서 검토하지 않으면 고지 불일치가 발생한다.**

| 변경 | 트리거 유형 |
| --- | --- |
| 통합 프로필 신설 — 관심 주제·저장 기사·콘텐츠 열람 이력 | 수집 항목 추가 |
| 행동 데이터 기반 개인화 추천 | 이용 목적 추가 |
| GA4 User-ID 도입(로그인 사용자 식별자 전송) | 처리위탁 + 식별자 결합 고지 |
| 뉴스레터 | **광고성 정보 수신 별도 동의**(정보통신망법). 회원가입 동의로 갈음 금지 |
| 외부 이메일 발송 SaaS 도입 | 처리위탁 + **국외 이전 고지 가능성**(추정 — 도입 시 확정) |
| 매거진 소셜 OAuth(Google·Kakao·Naver) 추가 | OAuth 권한 범위·연계 정보 고지 |
| 앱↔매거진 세션 연속성(SSO) 도입 | 서비스 간 개인정보 연계 고지 |

- 개인 식별 정보(이메일·이름·전화번호)를 분석 식별자로 전송하지 않는다. 비가역 식별자만 사용한다.
- 동의 없이 개인화·식별자 전송을 수행하지 않으며, 동의 철회 시 즉시 중단한다.
- 현행 동의 버전은 **약관·방침이 각각 별도 버전**이며, 두 곳에 같은 값으로 존재한다 — WordPress `inc/actions/account-privacy.php`의 `AMU24_TERMS_POLICY_VERSION`·`AMU24_PRIVACY_POLICY_VERSION`과 node-app `src/consts/legal/accountPolicy.ts`의 `CURRENT_ACCOUNT_POLICY`. **수치를 이 문서에 적지 않는다** — 착수 시 두 파일을 직접 조회하고 서로 일치하는지 함께 확인한다. 수집 항목이 바뀌면 **기존 회원 재동의 절차**를 함께 설계한다.
  > 2026-09-02 정정 — 종전에 적혀 있던 `AMU24_ACCOUNT_POLICY_VERSION`(값 `2025-10-25`)은 코드 어디에도 존재하지 않는 상수였다(AIR-002 실측).
- 상세 설계: `.agent/amu-platform-guide/AUDIENCE-AND-MEMBERSHIP.md` §9
- 정책이 보장한다고 고지한 이용자 권리에 대응 구현이 없으면 **구현을 만드는 것이 기본 방향**이다.
  정책 문구를 삭제해 갭을 없애는 처리는 이용자 권리 축소이므로 사용자 승인 없이 수행하지 않는다.
- 착수 전 `.agent/legal/open-issues.md`의 미해결 갭을 확인하고, 드리프트는
  `web-automation-project/wp_mng/legal_policy/detect_policy_drift.py`로 점검한다.

## 5. 운영 원칙

- 위 영역에 해당하는 작업 요청을 받으면, 보고서에 "규제 게이트 통과 여부"를 명시하고 미확정 항목은 `blocked` 사유로 기록한다. 단, 미성년 항목은 §3-1에 따라 `pass`로 기록한다(구현 트리거 해당 시 제외).
- 규제 판단이 불확실한 경우 "추정"으로 표기하고 법률 자문/공식 가이드라인 확인을 전제 조건으로 제시한다.
