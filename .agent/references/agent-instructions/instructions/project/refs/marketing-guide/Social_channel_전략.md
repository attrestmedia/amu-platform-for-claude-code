## 1. 결론 (구조 원칙)

블로그 외 소셜 채널은 **"같은 글을 여러 곳에 뿌리는 구조"가 아니라, 하나의 캠페인을 채널별 역할에 맞게 분해하는 구조**로 운영한다. 순서는 비즈니스 목표 → KPI → 채널 → 콘텐츠 → 성과이며, Campaign 객체를 중심으로 WordPress·네이버 블로그·Threads·Instagram·LinkedIn·뉴스레터를 묶는다 (`marketing_develop_plan.md` 참조).

표현 강도는 Charter §6의 **"표현은 과감하게, 사실은 보수적으로"**를 공통 기준으로 삼는다. 강한 문제 제기·감정적 확대·도발적 질문·극적 대비·실패담은 적극 허용하며, 수치·성과·기능·후기는 Charter §9의 검증과 §7.3의 투명한 참여 원칙을 적용한다.

```text
매거진               = 원본 인사이트 저장소
네이버 블로그         = 검색 유입 채널
Threads             = 실험 일지·생각 확산 채널
Instagram           = 시각 증거·템플릿 쇼케이스 채널
LinkedIn            = 전문성·대표 브랜딩 채널
YouTube Shorts/Reels = 제품 사용 장면 압축 채널
뉴스레터             = 관계 유지·재방문 채널
```

## 2. 공통 콘텐츠 필러 (5종)

전 채널 공통 필러를 먼저 정하고, 채널마다 비중만 달리 가져간다.

| 필러 | 내용 | 목적 | 추천 비중 |
| ------------- | ---------------------------- | ------- | ----: |
| AI 실전 활용 | 이미지 생성, 글쓰기, 프롬프트, 콘텐츠 자동화 | 제품 전환 | 35% |
| 1인 사업·마케팅 | 스마트스토어, 블로그, SNS, 상세페이지, 키워드 | 타깃 유입 | 25% |
| 빌드 인 퍼블릭 | AMU 개발/마케팅 실험/실패와 개선 | 신뢰·팬 확보 | 20% |
| 비즈니스·생산성 인사이트 | 대표 관점, 생산성, 업무 자동화, AI OS | 전문성 | 15% |
| 가벼운 브랜드 콘텐츠 | 짧은 생각, 밈, 비하인드, 인간미 | 친밀감 | 5% |

**매거진 소재(투자·패션·경제)를 그대로 소셜로 옮기지 않는다.** 항상 AMU와 연결되는 각도로 변환한다:

```text
패션 트렌드   → 의류 쇼핑몰 상세페이지에 AI 모델컷을 쓰는 법
경제/투자 글  → 대표가 시장 변화를 읽고 AI 콘텐츠 사업에 반영하는 방식
자기계발 글   → AI 시대 1인 사업자의 생산성 루틴
비즈니스 글   → 작은 팀이 콘텐츠 생산량을 늘리는 운영 시스템
```

## 3. 채널별 전략

### 3.1 Threads — 최우선 육성 채널

실험·실패·개선·짧은 인사이트가 잘 먹히는 구조로 AMU에 가장 잘 맞는다. 역할은 "검색"이 아니라 "사람 냄새 나는 확산".

| 카테고리 | 예시 |
| --------- | ----------------------------------------------- |
| 마케팅 실험 일지 | "이웃 2,000명 블로그를 버리고 새로 시작했습니다." |
| AI 활용 팁 | "AI 상품사진 만들 때 프롬프트보다 중요한 것." |
| 실패담 | "글 2,000개가 있어도 검색 유입이 안 나왔던 이유." |
| 운영 데이터 | "오늘 새 블로그 후보 글감 30개를 걸렀습니다." |
| 대표 생각 | "작은 팀은 콘텐츠를 많이 쓰는 게 아니라, 오래 살아남는 구조를 만들어야 합니다." |

운영 기준:

- 발행 리듬: 일일 draft 생성 cap 기준(`{{AGENT_ROOT}}/refs/content-policy/upload_cadence_and_quota.md`) **원본 하루 8건 이하 + 답글 활동 우선**. 빌드 인 퍼블릭은 주 2~3회까지 (도배 시 광고성 신호가 됨). 원본 도배보다 답글·대화량을 우선한다
- 링크 삽입은 5~7개 글 중 1개 정도만. 초반에는 전환보다 "팔로우할 이유" 우선
- 소셜 채널 중 가장 과감한 훅을 허용한다. 공식 계정의 첫 댓글 질문·추가 설명과 대표 계정의 실제 경험 보충으로 맥락을 확장하되, 가짜 계정·허위 체험담·직원 신분 은폐는 금지한다

### 3.2 Instagram — Gen Studio 쇼룸

글 채널이 아니라 **Gen Studio 결과물을 보여주는 쇼케이스**다.

| 카테고리 | 포맷 | 예시 |
| ------------ | ----- | ------------------------- |
| Before/After | 캐러셀 | "스마트폰 사진 1장 → 쇼핑몰 상세컷" |
| 템플릿 쇼케이스 | 카드뉴스 | "AI 상품사진 템플릿 5가지 활용법" |
| 프롬프트 미니팁 | 카드뉴스 | "모델컷이 어색할 때 바꿔야 할 3가지 문장" |
| 짧은 사용 시연 | Reels | "30초 안에 블로그 썸네일 만들기" |
| 사례형 콘텐츠 | 캐러셀 | "여성 의류 상세페이지 이미지 구성 예시" |

운영 기준:

- 집중 주제: AI 이미지 만들기, 쇼핑몰 상세페이지, 카드뉴스, 썸네일, 모델컷. 자기계발/경제 글은 올리지 않는다
- 발행 리듬: **주 2~3회**. 적게 올려도 "저장할 만한 결과물"이 있어야 한다
- 성과 분석 축: 이미지·캐러셀 성과, 저장·공유·댓글 (Marketing Ops 설계와 일치)
- Before/After는 같은 원본·조건·작업시간 기준과 보정 여부를 밝혀 시각 증거로 사용한다. 예시 결과는 `AI 생성 예시`임을 표시한다

### 3.3 LinkedIn — 대표 브랜딩 채널

대중 유입이 아니라 **전문성과 신뢰를 쌓는 채널**. 목표는 AMU 대표가 "AI 콘텐츠/마케팅 운영체제를 만드는 사람"으로 인식되는 것.

| 카테고리 | 예시 |
| -------- | ---------------------------------------- |
| 대표 관점 | "콘텐츠 생성 도구보다 마케팅 운영체제가 중요한 이유" |
| 산업 해석 | "AI 이미지 생성은 디자인 도구가 아니라 커머스 운영 도구가 된다" |
| 빌드 인 퍼블릭 | "검색 막힌 블로그를 버리고 새 채널을 설계한 과정" |
| 제품 철학 | "AMU가 단순 프롬프트 툴이 아니라 콘텐츠 성장 루프를 만들려는 이유" |
| 사례 분석 | "1인 셀러가 AI로 상세페이지 제작비를 줄이는 방법" |

운영 기준:

- 발행 리듬: **주 1회**, 대신 깊이 있게. Threads에서 반응 좋았던 글을 확장하는 방식 권장
- "꿀팁 3가지"보다 **왜 이 문제를 풀고 있는지**(대표의 관점)가 자산
- 관점과 문제 제기는 강하게 쓰되 수치·성과는 표본·기간·실험 조건·한계를 공개한다. "성공" 선언보다 검증한 것과 아직 검증하지 못한 것을 구분한다

### 3.4 YouTube Shorts / Reels — 후순위

Gen Studio는 생성 과정이 눈에 보여 영상화와 잘 맞지만, 운영 부담 때문에 Threads/Instagram 안정화 이후 착수한다. 초기에는 Reels와 Shorts에 같은 원본을 재활용한다.

| 포맷 | 예시 |
| --------- | ------------------------------ |
| 15초 결과 비교 | "이 사진이 이렇게 바뀝니다" |
| 30초 튜토리얼 | "AI 상품사진 만드는 과정" |
| 45초 사례 | "상세페이지 첫 화면 구성 바꾸기" |
| 화면 녹화 | Gen Studio 템플릿 선택 → 생성 → 결과 비교 |

### 3.5 뉴스레터 — 후순위, 장기 필수

소셜은 플랫폼 알고리즘에 휘둘리지만 뉴스레터는 **소유 가능한 관계 자산**이다.

- 초기 주제: 이번 주 AMU 실험 / AI 콘텐츠 팁 / 좋은 템플릿 / 마케팅·비즈니스 인사이트 / 실패와 개선
- 발행: **주 1회**. 매거진 유입이 일 1,000명 이상 안정화되면 구독 폼을 본격 배치

## 4. 채널별 역할 고정표

| 채널 | 핵심 역할 | 주력 주제 | 발행 리듬 |
| -------------------- | -------------------- | --------------------------------- | ----------- |
| Threads | 실험 확산, 관계 형성 | 빌드 인 퍼블릭, 짧은 인사이트, 실패담 | 주 5회 내외 |
| Instagram | 시각 증거, Gen Studio 쇼룸 | 이미지 템플릿, Before/After, 카드뉴스 | 주 2~3회 |
| LinkedIn | 전문성, 대표 브랜딩 | AI Marketing OS, 비즈니스 인사이트, 제품 철학 | 주 1회 |
| YouTube Shorts/Reels | 사용 장면 압축 | 생성 과정, 결과 비교, 미니 튜토리얼 | 후순위, 주 1~2회 |
| 뉴스레터 | 재방문, 관계 자산 | 주간 실험, 템플릿, 인사이트 큐레이션 | 후순위, 주 1회 |

> 일일 draft 생성량(생성 레버)과 발행 시각 분산(발행 레버)의 구체 상한·라우팅은 `{{AGENT_ROOT}}/refs/content-policy/upload_cadence_and_quota.md`를 기준으로 한다. 위 "발행 리듬"은 채널 역할 요약이며, 실제 강제 cap은 쿼터 문서가 우선한다.

## 5. 채널 적합도 게이트 (모든 글을 모든 채널에 뿌리지 않는다)

채널별 본문을 만들기 전에 **사전 적합도 게이트**를 통과해야 한다. 부적합하면 생성 자체를 스킵한다. 평가 축: 독자 적합성, 전환 연결성, 규격 실현성, 시의성·중복.

허용 기준:

```text
비주얼 증거가 있다            → Instagram 가능
짧은 실패담/실험 수치가 있다    → Threads 가능
대표 관점이나 B2B 인사이트가 있다 → LinkedIn 가능
검색 의도가 명확하다           → 네이버 블로그 가능
영상으로 보여줄 변화가 있다      → Shorts/Reels 가능
```

제외 기준:

```text
비주얼 없는 추상 글        → Instagram 제외
가벼운 잡담              → LinkedIn 제외
검색 수요 없는 운영 일지    → 네이버 블로그 제외
긴 설명형 글             → Threads에서는 요약/시리즈화
```

## 6. 초기 4주 운영안

```text
Threads: 주 5회 / Instagram: 주 2회 / LinkedIn: 주 1회
Shorts/Reels: 보류 / 뉴스레터: 보류
```

주간 콘텐츠 스케줄:

| 요일 | 채널 | 내용 |
| -- | -------------------- | --------------------------- |
| 월 | Threads | 이번 주 AMU 실험/마케팅 목표 |
| 화 | Instagram | Gen Studio 결과물 Before/After |
| 수 | Threads | AI 활용 팁 또는 실패담 |
| 목 | LinkedIn | 대표 관점의 긴 글 |
| 금 | Threads | 이번 주 데이터/배운 점 |
| 주말 | Instagram 또는 Threads | 가벼운 사례/템플릿 소개 |

## 7. 최종 방향

```text
Threads      = AMU의 살아 있는 실험실
Instagram    = Gen Studio의 결과물 쇼룸
LinkedIn     = 대표의 전문성 채널
Shorts/Reels = 제품 사용 장면 압축본
뉴스레터      = 관계를 오래 가져가는 소유 채널
```

**네이버 블로그는 검색으로 데려오고, Threads는 신뢰를 쌓고, Instagram은 결과를 보여주고, LinkedIn은 대표의 관점을 세운다.** 이 네 축이 맞물리면 AMU는 "AI 콘텐츠 도구를 홍보하는 계정"이 아니라 **AI로 콘텐츠와 마케팅을 실제 운영하는 브랜드**로 보이기 시작한다.

## 8. 캠페인·자동화 판단은 Charter를 따른다 (중복 정의 금지)

채널 운영 중 아래 판단이 필요하면 본 문서가 아니라 마케팅 정책 원장 `.agent/amu-platform-guide/MARKETING-STRATEGY.md`를 참조한다.

| 판단 | 위치 |
| --- | --- |
| 이 소재를 어느 축·CTA로 보낼 것인가 | Charter §5 라우팅 표 |
| 캠페인 정의(6요소)·소속 판정·상시 자산 허용 범위 | Charter §8.1~§5.2 |
| 단기 집중 발행(스프린트)을 시작해도 되는가 | Charter §8.3 착수 5조건 |
| 이 산출물은 어느 레인인가(S/T/H) | Charter §3 실행 레인 |
| 규격은 통과했는데 매력이 없다면 | Charter §7 Magnetism Score — 9점 이하 발행 금지 |
| 진행 중/종료 캠페인 현황 | Charter §8.4 캠페인 원장 |
| 가격·무료·기능 주장을 써도 되는가 | Charter §9 |
| 댓글·응답을 자동으로 내보내도 되는가 | Charter §10.1 권한 등급(L1/L2/L3) |
| 브라우저 자동화·비공식 클라이언트 사용 가부 | Charter §10.2 — **공식 API만 허용** |
| 고객 반론을 어떻게 처리하는가 | Charter §10.3 + `content_production_workflow.md` 6.5 |

- 개별 게시물 단위로 주제를 자유 선정하지 않는다. **운영 단위는 캠페인**이며, 채널은 하나의 캠페인을 역할별로 분해해 담는다(§1 구조 원칙과 동일).
- 캠페인은 발행량을 늘리는 근거가 되지 않는다. 편수 상한은 언제나 `{{AGENT_ROOT}}/refs/content-policy/upload_cadence_and_quota.md`가 강제한다.
