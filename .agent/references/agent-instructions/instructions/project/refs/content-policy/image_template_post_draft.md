# Image Template Post Draft Rules (이미지 템플릿 전용 기사 생성)

## 목표

1. 이미지 생성 프롬프트 템플릿을 소스로 하여, SEO가 잘 적용된 소규모 비즈니스 운영자를 위한 전문 기사 작성
2. 팀 구성 요청 시 비주얼 컨설턴트, 시나리오 플래너, 카피라이터, SEO 에디터, 휴머나이저로 구성된 5명의 팀메이트를 만들어 각 역할간 협업으로 최고의 결과물 생성

## 선행 규칙

- `{{AGENT_ROOT}}/refs/content-policy/magazine_knowledge_article.md` (기본 초안 작성 규칙)
- `{{AGENT_ROOT}}/refs/content-policy/writing_humanizer.md` (자연스러운 한국어 편집)

> 위 두 규칙을 기본으로 적용하되, 이 규칙의 추가 사항이 우선한다.

## 핵심 차별점 (기존 매거진 기사 작성 정본 대비)

1. 기사 작성 전 해당 기사의 `이미지 템플릿을 우선 등록`할 것
   - 등록은 `genstudio` MCP의 `upsert_image_prompt_template` 도구로 수행 (1차 호출은 `strictNew=true`)
   - 마크다운 → 페이로드 매핑은 `{{AGENT_ROOT}}/refs/genstudio-prompt-registration-guide.md`, MCP 도구 사용 일반 규칙은 `{{AGENT_ROOT}}/skills/amu-custom-mcp/SKILL.md` 우선 참조
2. **카메라 정보는 결과 차이 뒤에 설명**: 프롬프트 템플릿에 카메라·렌즈가 식별되고 그 설정이 결과 차이에 실제로 기여할 때만 특징·효과·추천 셋팅을 기술. 장비명 자체를 기사의 주인공으로 만들지 않고 시각 비교와 원리 설명 뒤에 배치
3. **프롬프트 예시**: 모든 프롬프트 생성 예시는 소규모 비즈니스 운영자 관점으로 작성(상품 촬영, 모델컷, 룩북, 배너, SNS 콘텐츠 등)하고, 반드시 `코드 블록` 문법 적용
   - 프롬프트 예시 작성 시 반드시 해당 프롬프트 예시 아래에 `![프롬프트 예시로 생성한 이미지 설명](assetId)`의 형식으로 이미지를 함께 추가할 것
4. **타깃 독자**: 소규모 비즈니스 운영자, 1인 셀러, 마케터
5. **내부 링크**: `amu-magazine` MCP로 실제의 포스트를 검색하여 관련 기사 1~2개만 추천
   - 콘텐츠 또는 이미지 프롬프트 관련 링크인 경우 반드시 **https://app.allmyuniverse.com/gen-studio?mode=image&view=detail&templateKey={templateKey}**의 형식으로 적용
6. **Slug 구조**: 기사의 슬러그는 반드시 `image-prompt-guide-{templateKey}` 구조로 생성
7. **메타 정보**: 메타 정보에 `templateKey`를 추가하여 해당 기사에 사용된 템플릿키 명시
8. **카테고리**: 카테고리는 하위 카테고리 `ai-creatives` **1개만** 설정한다. 상위 카테고리(`ai-work`)를 함께 넣지 않는다 — `magazine_knowledge_article.md` "카테고리 구조와 카테고리 slug"
   > 2026-09-12 정정: 종전에 적혀 있던 `amu-creatives`는 local·production 어느 WordPress에도 없는 slug다(실측). 실제 slug는 `ai-creatives`(부모 `AI & Work`)다.
9. **Content Experience Brief**: Primary Archetype은 기본 `make`, 보조 Archetype은 필요한 경우에만 `teardown` 또는 `experiment` 중 1개를 선택. E1 Story로도 완결되게 작성하고 실제 생성 연동은 승격·서비스 노출 게이트 통과 후에만 적용

## 기사 구조

1. **Question Hero**: 완성 결과나 Before/After를 먼저 보여주고, 독자가 해결하려는 제작 질문을 1문장으로 제시
2. **Evidence / Detection**: 성공 예시만 나열하지 말고 상품 변형·빛·원근·배경 등 독자가 먼저 관찰할 증거와 실패 지점을 제시
3. **Discovery**: 장비명·프롬프트 전문보다 먼저 결과가 달라진 핵심 원리를 설명
4. **Static Experience**: A/B 비교·오류 찾기·선택·예측 중 최소 1개를 두고 답과 판단 기준을 공개
5. **Make**: 상품 보존·사용 목적·스타일·배경처럼 결과에 중요한 선택부터 안내하고, 프롬프트 전문은 원리 이해 뒤에 배치
6. **검수와 한계**: 판매·발행 전 색·패턴·로고·기장·핏·오인 가능성을 확인하고, 실사와 AI를 구분해 써야 하는 경우를 설명
7. **Application**: 소규모 비즈니스의 실제 사용 장면과 의사결정 기준으로 연결
8. **Next Question**: 관련 기사·저장·후속 생성 중 Primary CTA 1개와 보조 행동 최대 1개. Gen Studio를 연결하면 다른 서비스를 같은 기사에서 함께 유도하지 않음

## 조건 블록 해설 기준

- 템플릿에 `{#if field == "value"}...{/if}` 블록이 포함된 경우, 기사에서는 조건문 자체를 개발자 문법처럼 길게 설명하지 않음.
- 독자에게는 "선택값에 따라 필요한 지시문만 자동으로 들어간다"는 사용 효과를 중심으로 설명.
- 이미지 템플릿에서는 캐릭터 타입, 배경, 구도, 표정, 레퍼런스 충실도처럼 결과 품질이 크게 달라지는 선택값을 중심으로 해설.

## 카메라 기종 정보 작성 기준

- 해당 기종의 대표적 이미지 특성 (색감, 해상도, 보케 등)
- 권장 촬영 셋팅 (조리개, ISO, 셔터스피드 범위)
- 해당 렌즈 조합의 장점과 적합한 촬영 상황
- 실제 촬영과 AI 프롬프트에서의 차이점/활용법

## SEO 특화 사항

- 포커스 키프레이즈: AI 이미지 프롬프트/상품 사진/쇼핑몰 이미지/소규모 비즈니스 관련 롱테일 키워드
- 프롬프트 예시 섹션에 구체적 비즈니스 키워드 삽입

## 금지 사항

- 일반적이고 낮은 퀄리티의 예시만 나열하는 것
- 소규모 비즈니스와 관련이 없는 맥락 없는 프롬프트 예시
- 성공 이미지만 나열해 AI 이미지 갤러리처럼 만드는 것
- 원리를 설명하기 전에 카메라 사양·프롬프트 전문·서비스 CTA부터 제시하는 것
- Gen Studio와 Tutors 등 서로 다른 서비스를 한 기사에서 동시에 Primary 경험으로 유도하는 것
- 조건 블록 문법 자체를 과도하게 설명해 독자가 프롬프트 활용보다 개발 문법에 집중하게 만드는 것
- 기존 `{{AGENT_ROOT}}/refs/content-policy/magazine_knowledge_article.md` 금지 사항 모두 동일 적용
