# Image Template Creation Rules (이미지 템플릿 프롬프트 생성)

## 목적

1. 이미지 또는 기존 프롬프트를 분석하여 **특정한 소재/분야에만 한정되지 않는 범용성**을 가지면서 **일관된 스타일**로 이미지를 생성할 수 있는 재사용 가능한 프롬프트 템플릿을 제작
2. 팀 구성 요청 시 프롬프트 엔지니어, 크리에이티브 디렉터, 비주얼 디벨로퍼로 구성된 3명의 팀메이트를 만들어 각 역할간 협업으로 최고의 결과물 생성

## 소재 라우팅 (착수 게이트 직전)

소비 원장은 `.agent/content/ai-prompts/image_templates/references/image_template_reference.md`다.
로컬 자료를 먼저 비우고 URL 자료로 넘어가며, 한 사이클에 1건을 소비한다.

**소재가 이미지 생성과 무관하면 템플릿을 만들지 않는다.** 해당 링크를 아래 문서로 옮기고
원장에서는 제거하며, 판정 근거를 한 줄로 함께 적는다.

| 소재 성격 | 옮길 문서 |
| --- | --- |
| 콘텐츠 생성 프롬프트 | `.agent/content/ai-prompts/content_templates/references/content_template_reference.md` |
| 영상 제작 | `.agent/content/ai-prompts/생성형_AI_동영상_테스트.md` |
| 기타(디자인·툴·그 외) | `.agent/content/ai-prompts/생성형_AI_기타.md` |

- 포스트가 아닌 URL(스레드 홈 피드 `threads.com/?xmt=`, 검색 URL)과 삭제·비공개로 접근 불가한 포스트는
  라우팅 대상이 아니라 **제거 대상**이다. 사유를 보고에 남긴다.
- 라우팅은 4축 판정보다 **먼저** 한다. 이미지 소재가 아닌 것을 이미지 템플릿 후보로 놓고 중복 검사를 돌리지 않는다.
- 소재가 이미지와 콘텐츠에 모두 걸치면(예: 이미지 안에 카피 문구를 넣는 프롬프트) 이미지 템플릿으로 처리하고,
  콘텐츠 원장에 중복 등록하지 않는다.

## 착수 게이트: 중복·유사 템플릿 선점 검사 (필수)

템플릿 수가 늘면서 **같은 개념이 key만 다르게 재등록되는 사고**가 누적되고 있다.
**신규 등록은 기본값이 아니다.** 아래 검사에서 중복·유사로 판정되면 신규 생성 대신 **기존 템플릿 개선(갱신)**으로 전환한다.

### 1단계 — 후보 조회 (소재 분석 직후, 등록 전)

`genstudio` MCP로 아래를 모두 조회한다. key 문자열 일치 검사만으로는 개념 중복을 잡을 수 없다.

```text
list_prompts({ promptType: "image", q: <핵심 개념어>, limit: 100 })   # 한글/영어 키워드마다 반복
list_prompts({ promptType: "image", category: <대표카테고리>, limit: 100 })  # 대표카테고리마다 반복
get_prompt_template({ templateKey: <상위 후보>, promptType: "image" })       # 후보 3~5건 본문 대조
```

- 검색어는 제목 문구가 아니라 **개념어**로 만든다(예: `누끼`, `합성`, `cutout`, `product`, `룩북`, `lookbook`).
- 조회에 실패하면 판정을 추정으로 대체하지 않고 **등록을 중단하고 `blocked`로 보고**한다(fail-closed).

### 2단계 — 정체성 4축 판정

| 축 | 이미지 템플릿의 판정 기준 |
| --- | --- |
| ① 산출물 유형 | 제품컷 · 인물/모델컷 · 룩북 · 배너/키비주얼 · 일러스트/아트 · 인포그래픽/도해 · 변환/합성 |
| ② 입력 의존 | 텍스트만으로 성립 vs 참고 이미지 필수(`inputPolicy.referenceImage.required`) |
| ③ 스타일 시스템 | 조명·색감·매체 표현(실사/애니/3D/수채 등)의 지배 축 |
| ④ 용도·배치 | 대표 `aspectRatio`와 사용 채널(상세페이지/SNS/배너/인쇄) |

- **3축 이상 일치 → 중복.** 신규 생성 금지. 기존 템플릿 개선으로 전환한다.
- **2축 일치 → 유사.** 기존 템플릿에 옵션·조건 블록으로 **흡수하는 것이 1순위**다. 아래 분리 허용 기준을 충족할 때만 신규 생성한다.
- **1축 이하 → 신규 생성.**

### 3단계 — 분리 허용 기준 (유사인데 신규를 만들어도 되는 경우)

하나 이상 충족해야 하며, 충족한 항목을 **판정 근거로 기록**한다.

- 흡수하면 고정 설정(조명/분위기/카메라)이 서로 모순되어 조건 블록 없이 성립하지 않고, 필요한 조건 블록이 12개를 넘는다
- 흡수하면 한 필드의 Select 옵션이 24개를 넘어 선택 피로가 생긴다
- `inputPolicy.referenceImage.required` 값이 서로 달라 한 템플릿에서 강제할 수 없다
- `defaultParams`의 지배값(`provider`·`aspectRatio`)이 서로 달라 기본값 하나로 수렴되지 않는다
- `accessLevel` 또는 운영 그룹이 달라 노출 대상이 분리되어야 한다

### 4단계 — 기존 템플릿 개선(갱신) 절차

1. `get_prompt_template`으로 현재 `templateText`·`defaultParams`·`inputPolicy`·`categories`·`tags`를 **전량 확보**한다.
2. 새 소재에서 **추가할 가치만** 추출한다 — 새 옵션 값, 새 조건 블록, 더 정확한 카메라/조명 서술, 보강 키워드.
3. 병합은 **가산만 허용**한다.
   - `key` 변경 금지 (rename 미지원)
   - 기존 변수명·옵션 라벨의 삭제·개명 금지 — 저장된 생성 이력·딥링크·조건 블록 참조가 깨진다. 불가피하면 사용자 승인 후 진행
   - 기존 고정 설정을 덮어쓰지 말고, 달라지는 지시는 **조건 블록으로 추가**한다
   - `categories`·`tags`는 합집합으로 만들고 상한(대표카테고리 2~4개, 키워드 각 10개) 초과분은 대표성이 낮은 값부터 제거
   - `usageTip`은 140자 상한 안에서 갱신
4. `upsert_image_prompt_template`을 `strictNew=false`, `version = 기존 version + 1`로 호출한다. **개선 목적의 `strictNew=false`는 이 절차를 거친 경우에만 허용**한다.
5. `get_prompt_template`으로 재조회해 병합 결과와 한글 표기를 검수한다(`{{AGENT_ROOT}}/rules/text-encoding-integrity.md`).
6. 템플릿 문서는 **기존 key와 같은 파일명으로 `completed/`의 문서를 갱신**하고, `new/`에 같은 개념의 새 문서를 남기지 않는다.
7. `content-ledger.jsonl`에 갱신 행을 append한다 — `type: "image-template"`, `status: "updated"`, `slug: <기존 key>`, `dedupeKey: "topic:<기존 key>"`, `source.summary`에 흡수한 소재 ref와 일치 축을 남긴다. 기존 행은 수정하지 않는다.

## 분석 절차

1. **이미지/프롬프트 정밀 분석**: 픽셀 단위로 세밀히 분석하여 카메라 기종, 색감, 구도, 조명 등 모든 시각적 요소를 식별
2. **스타일 시스템화**: 분석된 요소를 기본 설정으로 고정하여 다양한 인물/포즈/장면에 일관된 분위기를 재현할 수 있는 시스템 구축
3. **동적 요소 분리**: 선택 가능한 요소는 `{주제::옵션1|옵션2}`, 반드시 선택해야 하는 요소는 `{주제*::옵션1|옵션2}`로 표현
4. **조건 분기 분리**: 선택값에 따라 포함 여부가 달라지는 품질 지시문은 `{#if field == "value"}...{/if}` 블록으로 분리
5. **키워드 추출**: 해당 템플릿이 가장 효과적인 이미지 주제를 한글/영어 각 최대 10개의 1~2단어 키워드로 제시
6. **활용팁 작성**: 템플릿을 가장 효과적으로 활용할 수 있는 140자 이내의 안내글 작성

## 출력 템플릿 구조 (필수)

아래 구조를 반드시 준수하고, `genstudio` mcp를 사용하여 프로젝트에서 실제 사용 가능한 이미지 모델을 확인한 후 기본 설정 적용:

- 모델 선택과 샘플 생성은 `{{AGENT_ROOT}}/refs/content-policy/image_model_routing.md`를 따른다.
- **등록 검수용 대표 샘플**은 품질 자체가 템플릿 평가 대상이므로 `routingProfile=premium_template_sample`을 사용한다. Nano Banana 2를 우선하고 GPT Image 2.5 Flare를 폴백으로 사용한다.
- 템플릿 정의·메타데이터 작성만으로는 이미지를 생성하지 않는다. 샘플 생성은 비용 고지와 사용자 승인을 별도로 받은 경우에만 수행한다.
- 텍스트가 없는 템플릿 샘플은 `textPolicy=none`, 이미지 안의 읽을 수 있는 텍스트가 필수인 샘플은 `textPolicy=embedded_required`를 명시한다.

> 작성된 템플릿을 gen-studio DB(`image_prompts` 컬렉션)에 등록할 때는 `genstudio` MCP의 `upsert_image_prompt_template` 도구를 사용한다. 마크다운 → 페이로드 매핑·필수 검증 절차는 `{{AGENT_ROOT}}/refs/genstudio-prompt-registration-guide.md`를, 도구 사용 일반 규칙은 `{{AGENT_ROOT}}/skills/amu-custom-mcp/SKILL.md`를 우선 참조. 등록 전 **착수 게이트의 중복·유사 선점 검사**를 먼저 통과해야 하며, 신규 등록은 항상 `strictNew=true`, `strictNew=false`는 착수 게이트 4단계를 거친 의도된 갱신에만 사용한다.

### 강제 운영 정책: 기본 해상도와 참고 이미지

- **이미지 템플릿의 기본 생성 해상도는 최대 `1K`다.** Google 이미지 모델의 `defaultParams.size`는 반드시 `1K`로 등록하며, `2K`·`4K`를 템플릿 기본값으로 저장하지 않는다.
- 고해상도는 사용자가 개별 생성 시 명시적으로 선택하는 실행 옵션으로만 허용한다. 템플릿 제작자가 품질 향상을 이유로 기본값을 `2K` 이상으로 올리는 것은 금지한다.
- **첨부 이미지·원본 사진·스케치·도면·제품 컷·캐릭터/포즈 레퍼런스가 없으면 결과 목적이 성립하지 않는 변환·합성 템플릿은 `inputPolicy.referenceImage.required=true`를 반드시 적용한다.**
- 필수 참고 이미지 정책의 최소 계약은 `{ "required": true, "minCount": 1, "maxCount": <모델/용도에 맞는 값>, "enforceInCustomMode": true }`다. `required=true`인데 `minCount=0`으로 등록하지 않는다.
- `사진을 일러스트로 변환`, `피규어 포즈를 실사 인물로 변환`, `제품/누끼 합성`, `스타일·헤어 가상 시착`, `평면도/스케치 3D 변환`, `캐릭터 일관성 유지` 유형은 필수 참고 이미지 정책 대상이다.
- 참고 이미지가 결과 개선에 도움만 되고 텍스트 입력만으로도 템플릿 목적을 온전히 달성할 수 있는 경우에만 `required=false`를 허용한다.


```
# {스타일을 한 줄로 설명하는 제목}

{english-kebab-case-slug}

## 장면:

{인물/피사체 주제, 위치/방향, 배경/환경 등 사용자가 채울 가변 요소에 대한 안내}

## 대표카테고리:

{쉼표 구분 2~4개}

## 키워드:

{한글 키워드 최대 10개}, {영어 키워드 최대 10개}

## 활용팁:

{140자 이내 최적 활용 안내}

## 기본설정:

- `provider`: 해당 템플릿 이미지를 가장 팔 표현하는 모델
- `aspectRatio`: 해당 템플릿 이미지를 가장 잘 표현하는 비율
- `size`: **항상 최대 `1K`**. Google 기본값은 `1K`로 고정하며 `2K`·`4K` 금지
- `negative`: 해당 템플릿 이미지에 절대 포함되어선 안될 요소들

## 템플릿:

조명:
고정 조명 설정. 동적 요소는 {주제::옵션1|...} | {주제::설명} 형태

분위기:
고정 분위기 설정. 동적 요소는 {주제::옵션1|...} | {주제::설명} 형태

카메라:
렌즈/조리개/구도/해상도 고정 설정. 동적 요소는 {주제::옵션1|...} | {주제::설명} 형태

{기타}:
기타 이미지 생성 템플릿을 위한 추가적인 설정들 추가 가능
```

## 동적 요소 표기 규칙

- 형식:
  - 선택 Select: `{주제::옵션1|옵션2|옵션3}`
  - 필수 Select: `{주제*::옵션1|옵션2|옵션3}`
  - 선택 Input: `{주제::입력 받을 내용에 대한 설명}`
  - 필수 Input: `{주제*::입력 받을 내용에 대한 설명}`
- 필수 Select에는 `사용 안함`, `직접 설정`이 표시되지 않음
- 첫 옵션은 일반 화면의 기본값이며 외부 서비스의 기본값/잠금은 코드에서 주입
- 적용 대상: 색조, 광원 위치, 구도 등 장면마다 조절이 필요한 설정만
- 고정 설정과 혼동되지 않도록 명확히 구분하여 기술
- 모든 옵션은 해당 스타일 시스템 내에서 일관성을 유지하는 범위로 한정

### 확장 옵션 토큰 (`라벨; 설명; 프롬프트`)

- Select 옵션 하나를 `;`로 분절해 **화면에 보이는 라벨**과 **실제 프롬프트에 치환될 문장**을 분리한다.
  - `옵션값` (구분자 없음): 라벨 = 치환 문장. 치환 시 `normalizeLabel()`이 적용되어 `-`/`_`가 공백이 되고 단어 첫 글자가 대문자로 바뀐다
  - `라벨; 프롬프트`: 화면에는 라벨만, 프롬프트 분절은 **원문 그대로** 치환
  - `라벨; 설명; 프롬프트`: 라벨 + 검색형 셀렉트박스에 노출할 설명 + 원문 치환 (프롬프트 안의 `;`는 보존)
- **필수 사용 기준**: 옵션 값이 영어 지시문이거나 대소문자·하이픈·따옴표가 결과에 영향을 주는 경우
  (예: `[Composition] Classic Over-the-Shoulder (OTS) shot`, `f/16 deep focus`, `"step-printing" effect`)
  → 기본형으로 쓰면 `Over The Shoulder`처럼 변형되어 **프롬프트가 훼손된다**
- 한글 단문 옵션(`차분한 몽환`, `늦은 밤` 등)은 변형 위험이 없으므로 기본형을 유지한다. 불필요하게 확장 토큰으로 바꾸지 않는다
- 라벨은 사용자가 고르는 이름, 설명은 선택 근거(한 줄, 최대 72자 권장), 프롬프트는 모델에 전달할 실제 문장으로 역할을 명확히 나눈다
- 옵션 값 안에는 `|` `{` `}` 를 넣지 않는다(변수 토큰 문법과 충돌). `;`는 분절 구분자로만 사용한다
- 확장 토큰을 쓴 필드를 조건 분기에서 참조할 때는 **라벨로 비교**한다: `{#if 카메라 구도 == "오버 더 숄더 (OTS)"}`
- 옵션이 12개 이상이면 생성 화면이 자동으로 검색형 셀렉트박스 시트로 전환되며 전체 옵션 수가 함께 표시된다.
  이 경우 라벨/설명이 곧 검색 키워드가 되므로 라벨에 한글+영문 명칭을 함께 담는 것을 권장한다 (예: `오버 더 숄더 (Over-the-Shoulder / OTS)`)
- 옵션이 수십~수백 개인 템플릿은 관리자 UI 직접 편집이 비현실적이므로 `genstudio` MCP `upsert_image_prompt_template`로 등록·갱신한다

## 조건 블록 표기 규칙

- 형식:
  ```text
  {#if field == "value"}
  선택값이 value일 때만 최종 프롬프트에 포함할 이미지 생성 지시문
  {/if}
  ```
- 조건 블록은 `{#if ...}{/if}`만 허용.
- `else`, `elseif`, 중첩 조건, `and`, `or`, 정규식 조건은 사용하지 않음.
- 여러 선택값에 각각 다른 지시문이 필요하면 독립적인 if 블록을 나란히 작성.
- 조건에 사용하는 `field`는 반드시 같은 템플릿 안에 정의된 입력 변수여야 함
- 이미지 템플릿에서는 캐릭터 타입, 피사체 유형, 레퍼런스 충실도, 구도, 배경, 표정, 출력 목적처럼 선택값에 따라 결과 품질 지시가 달라지는 영역에만 조건 블록을 사용할 것.

## 품질 기준

### 기사 연결용 검증 메타 (해당 템플릿을 Magazine Evidence/Experience로 사용할 때만)

- 비교할 핵심 변수 1개와 `baseline / variant`를 정하고 나머지 생성 조건은 통제한다.
- 생성에 사용한 template key·version·model·assetId·핵심 설정을 기사 제작 근거에 남긴다.
- 단일 생성 결과를 일반적 인과관계나 성과 증거로 과장하지 않는다.
- 실패 결과도 상품 변형·구도·빛·텍스트 오류를 설명하는 Evidence가 되면 삭제하지 않고 편집 자산으로 보존한다.
- 이 메타는 기사 연결 템플릿에만 적용한다. 일반 이미지 템플릿의 DB 스키마를 Article Experience 필드로 확장하지 않는다.

- 착수 게이트의 선점 검사를 수행했고, 조회한 후보 목록과 4축 판정 결과를 근거로 남겼는지 확인
- 유사 판정인데 신규로 만든 경우 분리 허용 기준 중 어떤 항목을 충족했는지 명시했는지 확인
- 개선(갱신)한 경우 기존 변수·옵션이 하나도 삭제·개명되지 않았고 `version`이 1 증가했는지 확인
- 생성된 템플릿으로 실제 이미지를 만들었을 때 원본 스타일과 일관된 결과가 나와야 함
- 조명/분위기/카메라 3개 섹션 모두 충분히 상세하게 기술 (각 최소 2줄 이상)
- 카메라 기종이 식별 가능한 경우 반드시 기종명과 렌즈 스펙을 명시
- 기본설정의 `size`가 `1K` 이하이며 `2K`·`4K`가 아닌지 확인
- 영어 지시문을 옵션 값으로 쓴 Select가 **확장 옵션 토큰**으로 작성되었는지, 미리보기 프롬프트에서 하이픈/대소문자가 원문대로 유지되는지 확인
- 입력 이미지가 결과 성립에 필수인 변환·합성 템플릿은 `inputPolicy.referenceImage.required=true`, `minCount>=1`, `enforceInCustomMode=true`인지 확인
- 조건 블록을 사용한 경우, 선택값별 최종 프롬프트가 각각 독립적으로 자연스럽게 읽혀야 함
- 조건 설명(`human인 경우:`, `monster인 경우:` 등)을 최종 프롬프트 문장으로 남기지 말고 조건 블록 안의 실제 지시문만 남길 것

## 금지 사항

- 착수 게이트의 선점 검사 없이 새 key를 등록하는 것
- 같은 개념을 `-v2`, `-2`, `-new`, `-final` 같은 접미사를 붙인 새 key로 재등록하는 것 (버전은 `version` 필드로 관리)
- 중복 판정을 피하려고 제목·대표카테고리·키워드만 바꿔 등록하는 것
- 기존 템플릿의 변수·옵션을 삭제하거나 이름을 바꿔 갱신하는 것
- `CONFLICT`(409)를 만났을 때 key를 변형해 우회 등록하는 것
- 분석 없이 일반적인 프롬프트 나열
- 동적 요소를 고정값으로 하드코딩
- 템플릿 구조 항목 누락
- 조건 분기에 `else`, `elseif`, 중첩 조건, 복합 조건을 사용하는 것
- 존재하지 않는 변수를 조건 블록에서 참조하는 것
- 영어 지시문을 확장 옵션 토큰 없이 기본형 Select 옵션으로 넣어 프롬프트가 변형되게 두는 것
- 옵션 값 안에 `|`, `{`, `}` 를 포함시키는 것
- 과도한 키워드 제시 (한글/영어 각각)
- 원본 이미지/프롬프트와 무관한 스타일 요소 추가
