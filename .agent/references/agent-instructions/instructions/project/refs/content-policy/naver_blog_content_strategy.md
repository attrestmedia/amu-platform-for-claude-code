# Naver Blog Content Strategy Rules (신규 네이버 블로그 전용 콘텐츠 생성)

## 전제

- 대상: 신규 개설 네이버 블로그 (기존 블로그 검색 차단 진단에 따른 재출발)
- 역할: AMU 상단 퍼널 — 정보성 검색 유입 → Gen Studio/Tutors 체험 전환
- 소스: AMU 매거진(allmyuniverse.com) 기사를 네이버 전용 글로 **재조합** (복제 금지)
- 기존 블로그의 글을 새 블로그로 이전/재게시하지 않는다 (유사문서로 재출발하게 됨)

## 블로그 주제 정체성 (C-Rank 잠금)

- 한 문장: **"소상공인·1인 셀러·직장인을 위한 AI 실전 활용 블로그"**
- 네이버 블로그 주제 설정: `IT·컴퓨터` (AI 주제 밀도 기준)
- 발행 금지 주제: 게임 세계관 스토리, 투자/부동산, 자기계발 에세이 원문 톤, 보도자료형 서비스 소식
  - 위 주제의 매거진 기사는 네이버 재조합 대상에서 제외하거나, AI 활용 관점으로 완전히 재프레이밍 가능한 경우에만 사용

## 카테고리 구성 전략 (5개 고정)

| 카테고리(표시명) | 클러스터 키 | 다루는 것 | 발행 비중 | 전환 목표 |
|---|---|---|---|---|
| AI 이미지 만들기 | `ai-image` | 상품사진/모델컷/배너/썸네일 제작법, 프롬프트 템플릿 활용 | 35% | 창작 확장 (R1) |
| AI 글쓰기·콘텐츠 | `ai-writing` | 콘텐츠 프롬프트 실전, 블로그/SNS 글 자동화 | 25% | 창작 확장 (R1) |
| 1인 사업 마케팅 | `solo-marketing` | 스마트스토어/SNS 운영 팁, 마케팅 기초 | 20% | 관계 행동 (R2) |
| AI 첫걸음 | `ai-basics` | AI 용어/도구 비교/입문 가이드 | 15% | 학습 확장 (R1) |
| 만들면서 배운 것 | `build-log` | 빌드 인 퍼블릭, 개발 스토리 | 5% | 채널 구독·브랜딩 (R3) |

- 카테고리 신설/변경은 분기 리뷰에서만 허용 (임의 추가 금지)
- 발행 비중은 최근 20개 글 기준으로 점검하고, 특정 카테고리 연속 4회 초과 발행 금지

### 등록 클러스터·프로필 매핑 (귀속 판정용)

위 "클러스터 키"는 이 문서의 표기이고, 실제 귀속 판정은 `list_keyword_profiles`의 **등록 클러스터·프로필**로 한다.
2026-08-13 실측 기준 대응은 다음과 같다.

| 카테고리 | 등록 clusterKey | 등록 프로필 | 대표 키워드(앵커) |
| --- | --- | --- | --- |
| AI 이미지 만들기 | `ai-image` | `image-prompt-guide` | 굿즈 제작 (AI 이미지 생성) |
| AI 글쓰기·콘텐츠 | `ai-writing` | `ai-writing-content` | 글쓰기 AI (AI 글쓰기) |
| 1인 사업 마케팅 | `ai-marketing` | `solo-seller-marketing` | 사업 아이템 (AI 마케팅) |
| AI 첫걸음 | `ai-basics` | `ai-basics-guide` | 생성형 AI (AI 활용법) |
| 만들면서 배운 것 | `build-log` | `build-log` | 바이브 코딩 (AI 코딩) |

- 5개 카테고리 전부 등록 클러스터·프로필을 갖추었다(2026-08-13 `ai-basics` 클러스터와 `ai-writing-content`·`ai-basics-guide` 프로필 신설로 갭 해소). 이후 카테고리를 추가하려면 클러스터·프로필 등록을 먼저 사용자 승인받는다 — 미등록 상태로 글을 쓰면 `channel_fit_scoring.md`의 주제 귀속 선결 조건에서 **fail-closed로 걸린다**
- **앵커가 프로필마다 다르므로 `anchorIndex`를 프로필 간에 병합 비교하지 않는다.** 같은 앵커 안에서만 비교한다
- 이 문서의 카테고리 표기와 등록 클러스터가 어긋나면 **등록 클러스터가 기준**이다. 표기를 맞추려고 소재를 인접 클러스터에 억지로 귀속시키지 않는다
- 매핑은 실측일과 함께 갱신한다. 등록 상태는 MCP가 단일 출처이므로 이 표를 기억해서 쓰지 말고 매 사이클 재조회한다

## 매거진 → 네이버 재조합 규칙 (유사문서 방지, 필수)

1. **1소스 1글**: 매거진 기사 1개당 네이버 글 1개. `.agent/content/content-ledger.jsonl`에서 `naver:slug:{원본slug}` dedupeKey로 중복 확인 후 진행
2. **재사용 금지 3종**: 원문 제목, 원문 문단 구조, 원문 문장(연속 2문장 이상 동일 금지)
3. **재조합 절차**: 매거진 기사에서 핵심 인사이트 1개만 추출 → 네이버 검색 독자의 문제 상황으로 재정의 → 해요체 실용 가이드로 신규 작성
4. **관점 전환 필수**: 매거진(평어 에세이, "왜") → 네이버(해요체 가이드, "어떻게"). 어미만 바꾼 변환은 재조합이 아니며 금지
5. **이미지**: genstudio MCP 신규 생성 우선. 매거진 이미지 재사용은 글당 1개 이하
6. **원문 링크**: 매거진 원문 링크는 2~3글당 1회만 하단 참고로 표기 (매 글 동일 도메인 외부 링크 반복 금지 — 광고성 신호)

## 글 규격 (일관 품질 기준)

- 분량: 공백 포함 1,200~2,000자
- 제목: 롱테일 키워드 전방 배치 + 구체적 결과, 25자 내외 (예: "AI 상품사진 만들기, 스마트폰 사진 1장이면 돼요")
- 첫 문단: 공감 질문 또는 상황 묘사 + 키워드 1회 자연 삽입
- 구조: H2 3~6개(1개 이상에 키워드/유사 표현), 체크리스트 또는 표 1개, 마지막 요약 정리
- 어미: 해요체 통일 (`{{AGENT_ROOT}}/refs/content-policy/social_media_tone.md` 어미·존댓말 통일 규칙)
- 이미지: 2~4개 + 캡션, ALT 성격의 설명에 키워드 반영
- CTA: 글당 1개만 (Gen Studio 체험 또는 이웃추가), 본문 링크 최대 1개
- 발행 리듬: `{{AGENT_ROOT}}/refs/content-policy/upload_cadence_and_quota.md`의 naver_blog 일일 cap을 따른다 — Phase1 평일 2건·주말 1건(주 12건) → Phase2 3건 → Phase3 4건+(승급 조건 충족 시). 몰아서 발행·정각 대량 예약 금지
- 키워드: 발행 전 네이버 검색광고 키워드도구로 월 검색량/경쟁도 확인 권장, 미확인 시 "추정" 표기

## 내부 링크 클러스터 구축

- 단일 원장: `.agent/content/articles/queue/naver/cluster-map.json` (클러스터 정의 + 글 목록 + 발행 URL). **아직 생성되지 않았다** — 최초 클러스터 정의 시 이 경로에 만든다
- 발행 단계별 링크 규칙:
  - 1~5호 글: 내부 링크 0~1개 허용 (링크 대상 부족기)
  - 6호 이후: 같은 클러스터의 `publishedUrl` 기록 글 1~2개 링크 필수 + 허브 발행 후에는 허브 1개 링크 필수
  - 허브(필러) 글: 클러스터당 1개, 해당 클러스터 스포크 5개 이상 발행된 후 작성 ("완전 가이드"형 장문)
- 링크 방향: 새 글 → 과거 글 단방향이 기본. 발행된 과거 글 수정(역링크 삽입)은 월 1회 배치로 최소화 (잦은 수정은 지수에 부정적)
- `publishedUrl`이 기록되지 않은 글은 링크 대상에서 제외 (깨진 링크 방지)
- 발행 흐름: 에이전트(초안+링크 삽입+적합성 검증) → 사용자(검수·발행) → 사용자/에이전트(cluster-map에 publishedUrl 기록)

## 품질 게이트 (발행 전 필수)

1. 생성 전 `prepare_local_generation.contentFitStrategies`의 마케팅 기준과 이 문서의 블로그 목표를 함께 적용한 주제 하드 게이트 통과
2. `{{AGENT_ROOT}}/refs/content-policy/channel_fit_scoring.md` 기준 naver_blog `channelFit` **85점 이상**, `marketingFit` **85점 이상**
3. 유사문서 셀프 체크: 원문 제목/문장 재사용 여부 대조
4. `.agent/content/content-ledger.jsonl` 기록: `channel: "naver"`, `cluster`, `internalLinks`, `channelFit`, `marketingFit`, `adFit` 포함

### 주제-목표 마케팅 적합성 하드 게이트

- 본문을 쓰기 전에 소스 주제가 **"소상공인·1인 셀러·직장인을 위한 AI 실전 활용"**이라는 블로그 목표와 등록된 유니버스 마케팅 전략에 모두 맞는지 판정한다.
- **이 하드 게이트는 MCP 원장에도 반영돼 있다** — `marketingCriteria.channelGuidance.naver_blog` 15·16번, `excludedTopics` 14·15번(criteria version 12, 2026-08-13). 생성 시 대조 대상은 MCP 원장이며, 이 문서는 그 판정을 상세화한 것이다. **두 곳이 어긋나면 MCP 원장이 우선한다.**
  > 2026-08-13 이전에는 이 하드 게이트가 이 문서에만 있고 MCP 원장에는 없었다. 그래서 원장만 대조한 생성 에이전트가 자기계발·심리 소재를 `fit` 88로 통과시켰다(`marketing_job_9adb2359e52e4a0a987b397c60f1ab3e`). **판정 기준을 이 문서에만 추가하고 원장에 반영하지 않으면 같은 사고가 재발한다.**
- 5개 고정 카테고리 중 하나에 명확히 속하고 Gen Studio/Tutors 사용 장면 또는 자연스러운 전환 연결이 있어야 생성한다.
- 투자·부동산·패션 트렌드 단독·경제 전망·자기계발 에세이는 AI 실전 활용 관점으로 완전히 재프레이밍할 수 없으면 제외한다.
- 하드 게이트 실패는 점수 보정이나 억지 CTA로 통과시키지 않는다.
- 이미 enqueue된 job에서 제외할 때는 `submit_local_generation`에 본문 대신 다음 값을 제출한다: `channel: "naver_blog"`, `excluded: true`, `exclusionReason`, `validation`. node-app은 exclusion marker와 validation asset을 남기고 채널 step을 `skipped` 처리한다.

## 에이전트 작업 흐름 (소셜 콘텐츠 파이프라인 통합, 필수)

> 신규 네이버 블로그 글은 별도의 전용 TASK가 아니라, 기존 소셜 마케팅 콘텐츠 생성 흐름(marketing-ops 파이프라인, todo.json `TASK-COMMON` order 2)의 `naver_blog` 채널 산출물로 생성한다.

1. **소스 선정**: 소셜 파이프라인이 처리 중인 매거진 기사를 그대로 소스로 사용한다. 별도 후보 관리가 필요하면 `.agent/content/articles/queue/naver/sources.json`을 백로그로 활용(미생성 — 필요할 때 이 경로에 만든다)
2. **전략 확인**: `prepare_local_generation.contentFitStrategies`로 등록 마케팅/광고 기준과 버전을 확인하고 `{{AGENT_ROOT}}/refs/marketing-guide/*`를 함께 확인한다. 로드 오류 시에만 `get_content_fit_strategies`를 1회 호출한다.
3. **사전 게이트(Pre-Fit + 하드 게이트)**: 주제 정체성/카테고리/발행 금지 주제와 등록 마케팅 전략을 기준으로 판단한다. 실패하면 본문을 생성하지 않고 exclusion marker를 제출한다.
4. **중복 확인**: `.agent/content/content-ledger.jsonl`에서 `naver:slug:{원본slug}` dedupeKey 대조
5. **본문 작성**: 통과한 소스에만 재조합 규칙 + 글 규격을 적용하고 cluster-map.json 기준으로 내부 링크 삽입한다.
6. **검증/등록**: `channelFit`과 `marketingFit` 85점 이상 통과 후 naver_blog draft로 등록하고, `adFit`은 광고 소재 재사용 추천 정보로 별도 기록한다.
7. **기록**: ledger에 `channel`, `cluster`, `internalLinks`, 세 fit 요약과 전략 버전을 기록하고 cluster-map `posts`에 초안 항목을 추가한다.
8. **발행 루프**: 실제 발행은 사용자가 수동으로 진행한다. 발행 URL을 전달받으면 cluster-map의 `publishedUrl`을 갱신한다(사용자 트리거) — URL 미기록 글은 내부 링크 대상에서 제외

## 측정 루프 (4주 단위)

- 신규 글 발행 48시간 후 블로그탭 노출 여부 (목표: 4주차 노출률 50%+)
- Creator Advisor 검색 유입 비중, 주간 고유 유입 검색어 수
- 클러스터별 유입 편차 확인 → 발행 비중 조정은 분기 리뷰에서

## 금지 사항

- 매거진/WP 글 본문 복사 게시 (유사문서 방지 규칙 위반)
- 기존 블로그 글의 새 블로그 이전 게시
- 검색 수요 확인 없는 서비스 소식형 제목
- naver_blog 일일 cap 초과 발행(Phase별 상한 위반), 정각 대량 예약 발행, 몰아서 발행
- 근거 없는 수치/성과 서술 (필요 시 "추정" 표기)
