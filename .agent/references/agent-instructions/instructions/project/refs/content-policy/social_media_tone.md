- 운영 채널: 네이버 블로그 / 링크드인 / 스레드 / 인스타그램(2026-07 편입)
- 업로드 주기·일일 draft 생성 쿼터·대기 큐 라우팅은 `{{AGENT_ROOT}}/refs/content-policy/upload_cadence_and_quota.md`를 **단일 기준**으로 따른다(구체 cap 수치는 본 문서에 복제하지 않는다 — 드리프트 방지). 정각 1시간 간격 도배·저녁 슬롯 누락은 발행 측 가이드로 지양

- 전환 목표: `allmyuniverse.com` / `app.allmyuniverse.com` 방문자수 + 서비스별 구독자수 증가
- 콘텐츠 작성 언어: 한국어

## 정확도 가드레일

- 수치/성과/통계: 출처가 없으면 반드시 "추정"으로 표기하거나 제거
- 검색량/CPC 데이터: 에이전트가 임의로 확정치 생성 금지, 근거 링크 필수
- CTA/링크: 본문 중간 과다 삽입 금지, 마지막에 1~2회만 자연스럽게
- **가격·코인·보너스 문구**: 마케팅 정책 원장 `.agent/amu-platform-guide/MARKETING-STRATEGY.md` §6.1의 정책값만 인용한다(코인팩 보너스 최대 5%, 구독 보너스 5%, 충전은 부가세 별도). 팩별 보너스가 다르므로 "최대 5%"로 표기하고, 특정 팩을 말할 때는 팩 금액을 함께 밝힌다. **가입 보너스는 확인되지 않았으므로 사용 금지.** 가격·무료 코인·할인·환불 관련 신규 표현은 사람 승인(L3) 전 발행 금지
- **"무료" 표현의 범위 명시(필수)**: Gen Studio는 템플릿 열람·프롬프트 확인/복사가 무료이고 **생성 시 코인이 차감된다.** "프롬프트 무료"는 항상 생성 과금과 함께 쓰고, "모두 무료"·"무제한"·"마음껏"의 단독 사용은 금지 (Charter §9.2)
- **미구현 기능 소구 금지**: 소구 포인트로 쓰는 기능은 코드 또는 화면 캡쳐로 실재를 먼저 확인한다. 개발 중이면 "출시 예정" 표기 규칙을 적용하고 체험 CTA를 붙이지 않는다 (Charter §9.3)
- **CTA 축 선택**: 소재→축→CTA는 Charter §5 라우팅 표를 따른다. 금융·투자·세무·의료·법률 소재에는 Tutors 체험 CTA를 쓰지 않는다(자문 오인 방지)

## 소스 기반(Reference-first) 원칙

- 게시용 콘텐츠는 RSS/WP API로 확인된 소스(링크/슬러그/제목)를 기반으로만 생성
- marketing-ops 로컬 에이전트 산출물은 구조화 원문 근거(`outline`, `sourceQuotes`, `keyTerms`, `allowedClaims`)를 1차 근거로 삼고, validation에 `sourceCoverage`를 남김
- 소스가 없으면: “게시용 본문” 대신 “후보 소스 3개 제안 + 선택 요청”까지만 수행
- WP 원문/기존 글을 그대로 복사하지 않고, 채널 독자 관점으로 재구성(중복 게시 금지)

## 전환(Conversion) 원칙

- 목표: `allmyuniverse.com` / `app.allmyuniverse.com` 방문자 및 서비스 구독자 증가
- CTA는 1개만 선택(예: WP 글 읽기 / Gen Studio 체험 / 채널 구독)
- 링크는 채널 정책을 고려해 최소화(가능하면 프로필 링크 활용)

## 기본 원칙

- **표현은 과감하게, 사실은 보수적으로**: 강한 문제 제기·감정적 확대·도발적 질문·극적 대비·반전형 훅을 적극 사용하되, 실제 경험·확인된 문제·합리적 의견에 기반하고 본문에서 훅의 약속에 답함
- **공격적인 정직함**: 완벽한 척하기보다 한계와 실패를 먼저 인정하고 실제 효용을 선명하게 말함. 강한 표현 자체를 낚시로 감점하지 않음
- **타겟층 다양화**: WP 원문(자기계발/비즈니스/마케팅)에 고정되지 않고 일반 독자까지 포함
- **스타일 최적화**: 독자에게 유용한 정보를 공유하는 친근한 존대 구어체로 생성
- **어미 통일(필수)**: 모든 소셜 산출물은 친밀감 있는 존대어로 통일. 반말·평어 종결 금지(아래 "어미·존댓말 통일 규칙" 참조)

## 강한 표현 허용선

| 구분 | 처리 | 기준 |
|---|---|---|
| 감정·문제 확대 | 적극 허용 | 실제 경험이나 합리적 의견을 압축한 표현 |
| 도발적 질문·반전·비교 | 적극 허용 | 본문이 질문에 답하고 비교 조건을 숨기지 않음 |
| 미래 비전·가설 | 허용 | 현재 기능·실적과 명확히 구분 |
| 수치·성과 주장 | 조건부 허용 | 출처, 표본, 기간, 비교 조건, 측정 방식 확인 |
| 후기·추천·이벤트 참여 | 조건부 허용 | 실제 경험에 한정하고 소속·경제적 이해관계를 즉시 고지 |
| 허위 후기·가짜 댓글·신분 은폐 | 금지 | 제3자의 독립적 평가처럼 위장하지 않음 |

- 제목·첫 줄은 세게 쓸 수 있다. 다만 제목과 무관한 자극, 핵심 조건 은폐, 질문형 허위 주장, 근거 없는 최상급은 금지한다.
- 검증 전 수치는 "가능할까?" 같은 질문으로 우회하지 말고 `추정`·`목표`·`가설`·`업계 사례` 중 실제 성격을 밝힌다.
- 권장 흐름: **강한 문제 제기 → 솔직한 실험·한계 → 확인된 결과 → 분명한 CTA**.

## 어미·존댓말 통일 규칙 (필수)

- 모든 소셜 채널(네이버 블로그·링크드인·스레드·인스타) 산출물은 **친근한 존대어**로 통일.
- 채널별 기본 레지스터:
  - 네이버 블로그 / 스레드 / 인스타: **해요체 중심**(친근·다정한 정보 공유)
  - 링크드인: **습니다체 중심**(전문적이되 따뜻한 톤)
- 한 콘텐츠 안에서는 레지스터를 일관되게 유지. 해요체와 습니다체의 자연스러운 혼용은 허용하되, **반말과 존대의 혼용은 금지**.
- 매거진 평어/반말 종결은 소셜에서 금지: `~한다 / ~된다 / ~이다 / ~했다 / ~할 것이다 / ~까?` 형태로 끝내지 않음.
- **소스 톤 차단**: 소스(매거진 등)가 평어·반말톤이어도 소셜로 재가공할 때 반드시 존대어로 변환. 소스 어미를 그대로 옮기지 않음.

| 금지(평어/반말) | 권장(존대) |
|---|---|
| 한 컷 안에서 끝낼 수 있다 | 한 컷 안에서 해결할 수 있어요 |
| 같은 시스템 안에서 묶인다 | 같은 시스템 안에서 하나로 묶여요 |
| 구매 결정은 멈춘다 | 구매 결정이 멈춥니다 |
| 모델로 자리 잡았다 | 모델로 자리 잡았습니다 |
| 교체해 보면 어떨까? | 교체해 보시는 건 어떨까요? |

| 항목   | AllMyUniverse.com (WP 원문)  | 소셜미디어 (공통)          |

## Question-Discovery 채널 톤 (2026-08-24 신설)

제목·훅은 질문부터 만든다. 제목 자체가 답을 주지 않는다. 전문 지식을 대중이 지나칠 수 없는 질문으로 번역한다.

- **Threads**: 생각의 충돌 — `관찰 → 의외의 사실 → 짧은 해석`. 완전한 해설보다 팔로우할 이유를 먼저 만든다.
- **Instagram**: 설명보다 증거 — Before/After, 데이터 시각화, "보이지 않던 개념을 보이게".
- **Naver/검색**: Discovery Hook + Search Intent + 실행 가능한 답 결합(호기심만으로 끝내지 않는다).
- **공통 가드레일**: `Hook Strength ≤ Answer Strength`(질문이 답보다 강하면 안 됨), 검증되지 않은 숫자 훅 금지.
- **Question Loop 적용**: Threads는 스레드 자체를 질문 연쇄로(`관찰 → 의외 → 질문 → 기준 → 다음 질문`), LinkedIn은 질문을 대표 관점·산업 변화에 연결, Newsletter는 `이번 주 질문 → 부분 해답 → 새 문제 → 다음 호 질문`으로 연속성을 만든다.

## 채널별 톤 상세 가이드

### 네이버 블로그

**성격**: SEO 롱폼 / 검색 유입 최적화 / 유용한 정보 공유 및 전달

**제목 공식** (피드 직접 분석 기반):

- `[숫자/통계] + [핵심 주제]` → "5가지 공통점", "3가지 방법"
- `[대비 구도]` → "A vs B — 당신의 선택은?"
- `[의외성 도입]` → "몰랐다면 지금 알아야 할"
- `[연도 + 트렌드]` → "2026 AI 이미지 생성 완전 가이드"

**도입부 패턴**:

- 독자 공감 질문: "혹시 이런 경험 있으신가요?"
- 스토리텔링: "어느 날 갑자기..."
- 공감 → 반전: "어렵다고 생각하셨나요? 사실은..."

**금지**:

- 과장된 수익/성과 주장 제목 ("무조건 성공", "돈 버는 비법")
- 내용과 무관한 자극, 조건 은폐, 질문형 허위 주장
- 광고성 직접 홍보 문구 본문 삽입

**CTA**:

- 참고 기사 또는 원문 기사가 존재할 경우 하단에 해당 글의 "제목"과 "URL 링크" 적용

### 링크드인

**성격**: 전문 인사이트 / B2B + 일반 전문가 / SEO + 신뢰도

- 대표 관점과 문제 제기는 강하게 쓸 수 있다.
- 수치·성과 결론은 보수적으로 다루고 표본·기간·실험 조건·한계를 함께 밝힌다.
- "성공했다"보다 "무엇을 검증했고 어디까지 확인했는가"를 중심에 둔다.

**첫 줄 패턴** (스크롤 멈춤 유도):

- 반전 통계 + 인사이트 선언

**본문 구조**:

```
[첫 줄] 강렬한 인사이트 or 통계
[본문] 번호 리스트 3~5개 (간결하게)
[마무리] 전문가 의견 교환 질문
```

### 스레드

**성격**: 압축 정보 / 진정성 있는 인사이트 / 저장 및 팔로우 유도

> **가장 과감한 채널** — 강한 의견·실패담·도발적 질문·비교와 반전을 적극 허용한다. 공식/대표 계정의 후속 댓글로 근거와 맥락을 보충한다.

**형식**:

- 단독: 150~300자 핵심 정보 1개
- 시리즈: `1/5` → `2/5` → ... (주제별 깊이 있는 정보 전달)

**줄바꿈 규격** (차용 벤치마크 — AMU 실측으로 교정 대상):

Threads 피드는 모바일 세로 화면에서 스크롤로 소비된다. 줄바꿈은 장식이 아니라 읽기 속도를 만드는 구조이므로 아래를 형식 요건으로 취급한다.

- 한 줄 **40자 이하**를 기본으로 한다. 넘으면 절 경계(연결어미 + 쉼표)에서 끊는다.
- 문단은 **1~2줄**. 3줄을 넘기면 쪼갤 자리를 찾는다. 문단 사이는 빈 줄 1개(줄바꿈 2번).
- 모든 쉼표에서 줄을 바꾸지 않는다. **나열·숫자·짧은 동격 쉼표는 줄 중간에 그대로 둔다.** 기계적으로 토막 난 글이 된다.
- 줄의 기본 종결은 마침표다. 쉼표 줄바꿈이 절반을 넘으면 과용이다.
- **해시태그는 별도 등록이 되므로 본문에 포함시키지 않는다.** 자답글(reply)에는 0개 — 현재 발행 경로가 이미 이 형태이므로 회귀 방지 요건이다.
- 글자 수는 줄바꿈을 제외하고 센다. 줄바꿈을 늘려도 150~500자 판정에 영향이 없으니 길이를 아끼려고 줄바꿈을 생략하지 않는다.

### 인스타그램

**성격**: 비주얼 중심 정보 전달

- 카피보다 Before/After와 실제 결과를 가장 강한 훅으로 사용한다.
- 비교물은 같은 원본·조건·작업시간 기준을 사용하고, 보정 여부와 `AI 생성 예시` 여부를 밝힌다.

- 인스타그램은 소셜 콘텐츠 생성 루프의 기본 후보 채널에 포함하되, 사전 적합도 게이트(Pre-Fit)로 생성 여부를 판정 (`{{AGENT_ROOT}}/refs/content-policy/channel_fit_scoring.md`)
- 아래 조건은 Pre-Fit의 `feasibility`(규격 실현성) 판단 기준으로 사용하며, 하나도 충족하지 못하면 부적합(스킵) 처리
- marketing-ops 지원 채널 — 적합 판정 시 enqueue `channels`에 포함해 캡션 draft를 등록하고, 이미지는 `apply_channel_action(attach_image)`로 첨부(이미지 없이 완료 처리 금지). 카드뉴스 구성안/릴스 스크립트 등 보조 산출물은 `.agent/content/articles/social/instagram/`에 보관하고(디렉터리 미생성 — 최초 저장 시 만든다) 최종 발행 확정은 사용자가 검수 UI에서 진행 (사후 채점·ledger 기록은 동일 적용)
- **이미지 신규 생성 금지(2026-08-06 사용자 지시)**: 인스타그램 재가공에는 기존 자산만 쓴다. 소스 기사 본문 이미지, 같은 소재로 이미 생성해 둔 Gen Studio 자산, 템플릿 기존 샘플이 재사용 대상이며, 카드뉴스 장수를 채우기 위한 `generate_image` 호출은 하지 않는다. 확보한 장수에 맞춰 구성하고, 쓸 자산이 없으면 Pre-Fit `feasibility` 감점으로 스킵한다

**인스타그램 콘텐츠 적합 조건**(하나 이상 충족):

- 소스 기사 본문에 이미 사용된 이미지가 있음
- 같은 소재로 이미 생성된 Gen Studio 이미지 자산(asset/job) 또는 템플릿 기반 기존 샘플 이미지가 있음
- 위 자산으로 구성 가능한 범위에서 정보 밀도를 유지할 체크리스트/프레임워크가 소스에 포함됨
- 전후 비교(Before/After) 또는 단계별 튜토리얼이 핵심인 소스이고, 그 비교물이 이미 이미지로 존재함
