# Naver & Google Keyword Marketing Rules

## 목표

- 최소 예산으로 최대 효율의 키워드 전략 수립
- 기본 전략은 `롱테일 키워드(롱케일 포함 표현)` 중심으로 설계
- 브랜드/상업적/정보성 키워드는 필요 조건 충족 시에만 제한적으로 제시

## 기본 원칙

1. 모든 전략의 출발점은 롱테일 키워드다.
2. 짧고 경쟁이 높은 헤드 키워드는 기본안에서 제외한다.
3. 키워드는 "검색 의도 적합성 > 전환 가능성 > 비용 효율" 순으로 평가한다.
4. 채널별(Naver/Google)로 동일 키워드를 복제하지 말고, 검색 맥락에 맞게 분리 설계한다.
5. 예산이 제한적일수록 소수 고효율 키워드에 집중한다(키워드 확장보다 정밀도 우선).

## 키워드 유형 적용 규칙

### 기본 출력 규칙

- 기본 출력은 `롱테일 키워드`만 제시한다.
- 아래 3개 유형은 "반드시 필요한 경우"에만 추가한다.

### 조건부 출력 규칙

| 유형 | 기본 상태 | 추가 허용 조건 | 출력 시 필수 항목 |
|---|---|---|---|
| 브랜드 키워드 | 기본 제외 | 브랜드 방어/인지 캠페인 명시, 경쟁사 브랜드 입찰 대응 필요, 브랜드 검색 수요가 실제 핵심 퍼널일 때 | 제시 사유, 예상 효익, 제외 시 리스크 |
| 상업적/상품 키워드 | 기본 제외 | 구매/문의/신청 전환 목표가 1순위이고, 랜딩/오퍼가 준비되어 있으며 CPC 감당 가능할 때 | 전환 목표, 예상 CPA 영향, 예산 배분 이유 |
| 정보성 키워드 | 기본 제외 | 상단 퍼널 유입 확보가 현재 병목이며, SEO/콘텐츠 확장이 명확히 필요한 단계일 때 | 전환 연결 경로, 콘텐츠-전환 연결 CTA |

## 채널별 실행 기준

### Naver

- 메시지 프레임: 네이버 검색자는 "지금 살/쓸 사람" — 실용·후기·커머스 맥락 우선
- 블로그/View/지식iN/카페 문맥을 반영한 자연어 롱테일을 우선 발굴
- 상업 키워드라도 정보 탐색형 문장 패턴(예: 비교, 후기, 추천 기준)을 우선 검토
- 내부 콘텐츠 자산(기존 포스트)과 연결 가능한 키워드를 우선순위 상단에 배치

### Google

- 메시지 프레임: 구글 검색자는 "문제를 찾는 사람" — 프롬프트·작성법·해결형·글로벌 맥락 우선
- 검색 의도(Informational/Commercial)와 랜딩 목적의 정합성을 최우선으로 맞춘다
- 광고용은 전환 의도 롱테일 우선, SEO용은 문제 해결형 롱테일 우선
- 동일 주제는 클러스터로 묶어 중복 경쟁을 줄인다(광고 그룹/콘텐츠 허브 기준)

## 키워드 검증 도구 활용 (필수)

목적: "추정"이나 데이터랩 상대 지수만으로 키워드를 확정하지 않고, 실제 검색량·경쟁도·전환 데이터로 검증한다. 단, 모든 콘텐츠에 동일한 강도로 적용하지 않는다 — 콘텐츠 성격에 맞는 검증 강도를 먼저 선별한다.

### 적용 대상 선별 (최우선)

검증 강도는 3단계다.

- **Full(3단 검증)**: 아래 "순서" 1~3번을 모두 수행
- **Light(트렌드만)**: "순서" 1번(`get_naver_keyword_trend`)만 수행, 2~3번 생략
- **Skip**: 도구 호출 없이 진행(단, 검증하지 않았다는 사실 자체는 결과물에 명시 — "고효율" 등 근거 없는 단정 금지는 그대로 유지)

콘텐츠 R 등급(`.agent/amu-platform-guide/MARKETING-STRATEGY.md`의 "R Routing" 절, R0~R4)과 유형에 따라 아래 표로 강도를 정한다.

| 콘텐츠 유형 | 강도 | 사유 |
|---|---|---|
| WP 매거진 신규 기사 (R0/R1 — 시리즈·클러스터 소재, 이미지·콘텐츠 프롬프트 가이드 등) | Full | 검색 유입이 신규 독자 확보의 핵심 경로, 광고 없이 SEO만으로 승부 |
| naver_blog 신규 포스트 (TASK-COMMON 파이프라인, AI 이미지/AI 글쓰기/1인 사업 마케팅/AI 첫걸음 카테고리) | Full | 신규 블로그 자체의 목적이 검색 유입 회복(`{{AGENT_ROOT}}/refs/content-policy/naver_blog_content_strategy.md`) |
| 광고 → SEO 회수 루프 파생 기사 (`{{AGENT_ROOT}}/refs/content-policy/measurement_and_conversion.md`) | Full + Ads 성과 | 광고 전환이 이미 검증된 최우선 소재 |
| naver_blog build-log 카테고리 (실제 개발·제작 근거가 있는 소재) | Light | 목적이 검색 경쟁이 아니라 브랜딩·진정성 — build-log는 발행 비중 5%의 브랜딩 필러 |
| WP 매거진 리라이팅(기존 slug 유지) | Light | 키워드·slug 이미 고정, 트렌드 변화만 참고해 문구 보정 |
| threads/linkedin/instagram 소셜 재가공(원문의 파생) | Skip | 원문(WP/naver_blog) 단계에서 이미 검증 완료 — 같은 소재를 재검증하면 API quota만 낭비 |
| P3(Store/Play 브랜딩)/P4(매거진 일반 유입) 성격의 콘텐츠 | Skip | 전환 기여가 낮아 실측 도구 비용을 들일 우선순위가 아님. 사용자가 특정 소재의 성과를 명시적으로 요구하면 그때만 Light로 승격 |

표에 없는 새 콘텐츠 유형은 기본값을 **Light**로 하고, Full 또는 Skip으로 단정하기 전에 사용자에게 확인한다.

### 키워드 프로필 원장 (검증 착수 전 확인)

`get_naver_keyword_trend`의 `anchorIndex`는 **같은 anchorKeyword 안에서만 비교 가능하다.** 프로필은 그 앵커를 클러스터 단위로 고정하고, 후보 키워드(`seedKeywords`)와 선정 이력(`selectedKeyword`/`selectedReason`)을 축적하는 원장이다. 프로필 없이 조회하면 매번 `settings.defaultAnchorKeyword` 하나로 떨어져 서로 다른 주제의 지수가 같은 기준으로 찍히고, 후보 키워드도 매 건 새로 만들게 된다.

**착수 전 확인**: `list_keyword_profiles`의 `profiles`가 비어 있거나 대상 주제의 클러스터에 프로필이 없으면, 본문 생성 전에 프로필을 먼저 등록한다.

- 클러스터(`clusters`)는 최초 조회 시 seed가 자동 부트스트랩되지만 **프로필은 자동 생성되지 않는다.** 비어 있는 것은 장애가 아니라 미등록 상태다.
- 등록 경로는 두 가지다. 운영자는 Marketing Ops 관리자 화면의 `키워드 전략` 탭, 에이전트는 `marketing-ops` `upsert_keyword_profile`을 사용한다. DB 직접 쓰기는 금지한다.
- 프로필이 없는 상태로 진행해야 하면 차단하지 말고 기본 앵커로 검증하되, 결과물의 keyword 블록에 `profileKey: ""`와 미등록 사유를 남긴다.

**등록 단위**: 프로필은 게시물이 아니라 **클러스터 또는 캠페인 단위**로 만든다. 글마다 프로필을 만들면 앵커가 파편화되어 비교 자체가 무의미해진다.

| 필드 | 규칙 |
|---|---|
| `profileKey` | ASCII slug 고정(`a-z0-9-_`). 한글은 `name`에만 쓴다 |
| `clusterKey` | `list_keyword_profiles`의 `clusters`에 실재하는 활성 키만 사용. 없는 키는 등록이 거부된다 |
| `anchorKeyword` | 클러스터 성격에 맞는 기준 키워드 1개. 비우면 `settings.defaultAnchorKeyword`를 따른다 |
| `seedKeywords` | 해당 클러스터에서 반복 검증할 후보 키워드(최대 20개). 검증할 때마다 쓴 후보를 누적한다 |
| `selectedKeyword` / `selectedReason` | 대표 키워드 확정 후 **되기록**한다. 근거에는 `anchorIndex`·`momentum`·`seasonality` 실측치를 포함한다 |
| `campaignId` | 소속 캠페인이 있을 때만. 상시 자산이면 비운다 |

**앵커 변경 가드**: 기존 프로필의 `anchorKeyword`를 바꾸면 그 이전에 수집한 `anchorIndex`와 비교가 단절된다. 에이전트 경로는 `confirmAnchorChange=true` 없이는 409로 차단되며, 변경 시 `anchorChangedAt`이 기록된다. 앵커는 클러스터 성격이 실제로 바뀔 때만 변경하고, 점수가 낮게 나온다는 이유로 바꾸지 않는다.

**부분 갱신**: `upsert_keyword_profile`은 전달하지 않은 필드의 기존 값을 유지한다. 다만 `seedKeywords`처럼 배열을 전달하면 **해당 필드는 통째로 교체**되므로, 기존 후보에 추가하려면 조회한 목록에 새 항목을 더해 전체를 보낸다.

**금지**: 프로필을 성과가 나쁘다는 이유로 비활성화하거나 새로 만들어 앵커를 갈아타는 방식으로 지수를 리셋하는 행위. 검증 이력이 끊어지면 클러스터별 비교 표본이 사라진다.

### 순서 (Full 기준)

1. 시드 브레인스토밍 후, 후보 키워드 3~5개를 `marketing-ops` `get_naver_keyword_trend`(anchorKeyword 또는 profileKey 지정)로 1차 스크리닝한다 — momentum이 음수이고 seasonality가 declining인 키워드는 제외 후보로 표시한다.
2. 살아남은 후보는 `naver_ads_keyword_ideas`(최대 5개)로 실제 월간 검색량·경쟁도를 확인한다. Google 대상 키워드는 `google-marketing` `google_ads_keyword_ideas`로 동일하게 확인한다(언어 1012/한국 지역 기본값 사용).
3. naver_blog 발행이 목적인 키워드는 `analyze_naver_serp`로 competitionTotal·recent30dRatio를 확인한다. 경쟁 문서가 과포화(최근 30일 발행 비중 높음)면 `topTitles`를 참고해 차별화 앵글을 찾거나 해당 키워드를 후보에서 제외한다.
4. 위 단계를 통과한 키워드만 최종 후보로 남기고, 아래 "실행 절차" 5번 스코어링에 실측치로 반영한다.
5. 주 1회 배치 점검은 `refresh_keyword_candidates_naver`(limit 40, withSerp)로 candidate 큐 전체를 일괄 검증한다 — 매 건 수동 조회 대신 정기 스캔으로 대체한다. 이 배치는 Full 대상 콘텐츠의 candidate만 포함한다.

### naver_blog 채널의 운영 절차 연계

naver_blog 대상 키워드 검증의 **운영 실행 순서**는 `.agent/todo-ledgers/tasks/todo-content.json` TASK-COMMON order 2의 2.0 절차(`list_keyword_profiles` → 프로필 없으면 `upsert_keyword_profile`로 등록 → `get_naver_keyword_trend`(profileKey, 캐시 우선) → 필요시 `analyze_naver_serp` → 대표 키워드를 프로필에 되기록 → 검증 결과를 validation_report의 keyword 블록·content-ledger에 기록)를 따른다. 위 표에서 naver_blog가 **Full**로 판정된 경우, 2.0 절차에 더해 `naver_ads_keyword_ideas`로 실제 월간 검색량까지 확인한다. **Light**로 판정된 경우 2.0의 트렌드 확인까지만 수행하고 실검색량·SERP는 생략한다. 즉 2.0은 운영 실행 스펙, 이 섹션은 검증 강도(Full/Light/Skip) 판정 기준이며 서로 대체가 아니라 계층 관계다.

### 데이터를 얻을 수 없을 때

- 위 도구가 자격증명 미구성/일시 오류로 실패하면 데이터랩 상대 지수만으로 진행하되, 결과물에 "실측 검색량·경쟁도 미확인"을 명시한다. 추정 수치를 만들어내지 않는다.

## 실행 절차

1. 목표 정의: 리드/판매/트래픽 중 1차 KPI를 명시
2. 제약 확인: 월 예산, 집행 기간, 채널 우선순위 확정
3. 시드 추출: 제품/문제/대상/상황 단위의 시드 키워드 작성 후 위 "키워드 검증 도구 활용" 절차로 실측 검증
4. 롱테일 확장: `[대상] + [문제] + [상황] + [해결/비교/방법]` 패턴으로 확장
5. 스코어링: 의도 적합성, 전환 가능성, 경쟁도, 비용을 기준으로 우선순위화(경쟁도·검색량은 3번에서 확보한 실측치 사용, 추정 금지)
6. 채널 분배: Naver/Google 별로 중복 최소화하여 역할 분리
7. 조건부 유형 검토: 브랜드/상업적/정보성 키워드 필요 여부를 조건표로 판단
8. 실행안 확정: 예산 배분, 콘텐츠/캠페인 단위 액션, 측정 지표 정의

## 출력 형식(필수)

1. 전략 요약 (목표, 예산, 채널 우선순위)
2. 롱테일 핵심 키워드 리스트 (채널/의도/우선순위/활용처 포함)
3. Naver 실행안 (콘텐츠/광고/링크 구조)
4. Google 실행안 (SEO/검색광고 그룹 구조)
5. 측정 계획 (CTR, CPC, CVR, CPA, 검색순위/유입) — 이벤트/UTM 표준과 판정 지표는 `{{AGENT_ROOT}}/refs/content-policy/measurement_and_conversion.md`를 따른다 (판정은 클릭이 아니라 가입 CPA → 첫 생성률 → 충전 CPA)
6. 조건부 키워드 제시 여부
   - 제시한 경우: "왜 필요한지"와 "예산 영향"
   - 제시하지 않은 경우: "현재 제외 이유"

## 금지 사항

- 근거 없이 브랜드/상업적/정보성 키워드를 관성적으로 나열하는 행위
- 롱테일 검토 없이 헤드 키워드부터 제안하는 행위
- 측정 근거 없이 "고효율"이라고 단정하는 표현
- 채널별 의도 차이를 무시한 동일 키워드 복붙

## 최종 체크리스트

- 대상 클러스터의 키워드 프로필이 등록되어 있고, 확정한 대표 키워드를 프로필에 되기록했는가
- 비교에 쓴 `anchorIndex`가 모두 같은 `anchorKeyword` 기준인가
- 롱테일 중심 구조가 명확한가
- 조건부 키워드 제시 시 사유가 구체적으로 기록되었는가
- 예산 절감 논리가 키워드 우선순위와 연결되는가
- Naver/Google 실행안이 각각 분리되어 있는가
- KPI와 측정 항목이 실행 가능하게 정의되었는가
